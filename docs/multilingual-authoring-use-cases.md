# 多言語原文・手動翻訳・原稿取り込みのユースケース整理

更新日: 2026-09-12
状態: ユースケースと調査時点の記録。2026-09-13に原文言語の作成UI・通常翻訳表示・既定言語設定を実装。全文取り込み等は設計案。保存仕様は維持。
調査対象: feature/flow-layout-foundation / 2f01cc9
関連: [言語表示とヘルパー計画](editor-language-and-helper-plan.md)

## 言語の役割を分ける

| 役割 | 現在の保存/設定 | UI上の扱い案 |
|---|---|---|
| 操作画面の言語 | 端末のUI設定。JA/EN | プロフィール内。原稿や翻訳先を決めない |
| 作品の既定言語 | project.defaultLang | 作品情報や新規Flowの初期値。既存Flowの原文を変更しない |
| Flowの原文言語 | flow.document.sourceLanguage | 翻訳の基準・共通段落構造の編集元。Flow作成時に明示 |
| 表示・編集する本文言語 | state.activeLang | キャンバス上で選択。通常/分割で同じ意味にする |
| 翻訳先 | textsの言語キーと翻訳処理の対象 | 手動・外部原稿・機械翻訳で同じ本文欄を利用 |
| 組版とページ進行方向 | 言語別typography / languageConfigs | UI言語と独立。日本語でも縦書き・横書きを選ぶ |

原文は日本語の同義語ではない。英語→日本語、韓国語→英語等を同じモデルで扱う。
言語コードを保存できることと、その文字体系の組版/フォント/入力をサポートすることは別。現在のwriting mode判定は日本語、簡体字、繁体字、韓国語、ラテン文字を対象とする。アラビア語等の全言語対応は別途検証なしに約束しない。

## 現状の裏付けと不足

- FlowDocumentは任意の原文言語キーを持てる。英語原文のmodel検証も存在する。ただし一連の製品UIが英語原文で十分検証されたことを意味しない。
- 新規プロジェクトの初期化はja、Flow追加はdefaultLangを優先する。作成される見出しなどにも日本語固定文言が残る。
- プロジェクト設定の言語列並べ替えがdefaultLangを変更する。単なる並べ替えと既定言語設定を分離すべき。
- 既存FlowのsourceLanguageは表示言語やdefaultLangの変更では変わらない。原文言語の削除には保護がある。原文言語の移行UIは別課題。
- 見出し・段落IDを共有し、同じblock.textsに言語別本文を保存する。対応はページ番号や行番号によらない。
- 原稿画面とキャンバスの段落入力から手動翻訳を保存できる。pasteはplain textを扱う経路があり、段落内改行をそのまま複数の対応段落に自動分配する機能ではない。
- 翻訳側では共有段落構造の分割/結合に制限がある。通常画面で未翻訳を編集できない問題はL1で先に修正する。
- 機械翻訳には手動訳保護、原文変更後の確認状態、更新結果の照合がある。取り込み後も同じ経路を使い、保護の別実装を作らない。

## ユースケース

| ケース | 目標の操作 | 方針/不足 |
|---|---|---|
| 英語の新作を作り日本語版も出す | 新規作成で原稿言語English、横書きを選び、日本語版を追加 | モデルを活用。作成UIと初期文言を整備 |
| 日本語UIで英語の原稿を編集する | UI日本語、原文EN-GB、翻訳先JAを独立して選択 | UI言語から原文を強制しない |
| 翻訳を一切使わない | 原文だけ入力し発行 | 翻訳操作を必須にしない |
| 最初から自分で翻訳する | 対象言語の空欄に入力。分割で原文を参照 | AI設定/APIキー不要。L1で通常表示も対応 |
| 他サービスで翻訳した一段落を貼る | 対応段落を選び翻訳欄へ貼り付ける | 手動入力と同じ編集/Undo/保護。HTML書式は初期対象外 |
| 外部の翻訳済み全文/章を取り込む | 翻訳原稿の取り込み→原文との対応確認→適用 | 新規の取り込みUIが必要。通常pasteとは分離 |
| 原文と翻訳で段落数が違う | 原文の一段落へ訳の複数段落をまとめる等、対応を確認 | 初期は一つの原文block内の改行で表現。独立構造/多対多対応は別設計 |
| 一部手動、残りを機械翻訳 | 未翻訳を対象に実行。既存手動訳は保護 | 既存の対象選択/lockを再利用。上書きは件数と対象を明示 |
| 原文を後から修正する | 既存訳を残して対応段落だけ要確認表示 | 再翻訳を強制しない。目視確認後の確認済み操作を提供 |
| EN-GBからEN-USの地域版を作る | 別言語キーとして用意し表現を調整 | 自動で同一視しない。原文基準で管理 |
| 一作品に原文言語が異なるFlowを入れる | Flowごとに原文表示し、選択Flowの言語を基準に比較 | モデル上可能。全作品翻訳・混在Flow比較は追加検証対象 |
| 英語訳を元に第三言語へ翻訳する | 翻訳元を明示して実行したい | 現行翻訳処理はFlow原文基準。中間訳の依存追跡は未設計 |
| 途中で英語版を原文に昇格する | 原文言語を変更したい | 通常言語切替で行わない。確認状態、構造、参照の移行を別単位で設計 |

## 新規作成・表示UI案

- 新規作品に「最初の原稿の言語」「書字方向/ページ方向」を設け、作品の既定言語を初期化する。UI言語から初期候補は出せても確定は利用者が行う。
- Flow追加は「原文言語」を明示し、作品の既定言語を初期値にする。EN-GBを閲覧中というだけで既存Flowの原文を変更しない。
- 本文言語付近に「原文: English (UK)」を短く表示し、対象Flowが変われば更新する。
- 翻訳作成の入口には「手入力」「原稿を取り込む」「機械翻訳」を用意する。手入力は通常の本文編集を開き、AIの登録を要求しない。
- 分割の左見出しは「原文・EN-GB」等の実データを使う。ヘルプも日本語原文を前提に書かない。

## 翻訳原稿の取り込み案

1. 対象Flow/章、翻訳先言語、入力テキストを選ぶ。初期はplain text貼り付けを対象にし、DOCX/PDFの書式付き取り込みを同時に増やさない。
2. 原文と貼り付け原稿の段落候補を並べる。空行区切り等の分割方法をプレビューし、入力の改行だけから無確認で対応を決めない。
3. 段落数が一致しても対応候補に留める。見出し、空欄、原文のみ/訳文のみ、途中抜粋、段落統合を可視化する。
4. 初期版は原文の見出し/段落IDへ文字列を割り当てる。必要なら原稿側の複数段落を一つの訳文欄内の改行として保持する。複数原文への恣意的な分割や複製はしない。
5. 未翻訳への追加を既定にし、既存訳/手動保護を上書きする場合は該当箇所を明示選択する。「対象外」と「意図した空訳」を区別する。
6. 適用直前に変更件数、未対応箇所、上書き箇所を表示する。対応確認中に原文/既存訳が変われば再確認し、古い案を適用しない。
7. 検証済みの一括変更を既存の手動編集経路へ接続し、一回のUndoで戻せるようにする。表示確認だけで保存/確認状態を変更しない。

対応表はまず取り込みセッション内のデータとし、既存のtexts/段落ID/手動編集メタデータへ適用する。訳独自の段落構造、多対多の永続対応、翻訳元の系譜、取り込み元ファイルの保存を必要とする場合は新しい保存仕様を別途提案する。

## 計画への組み込み

- L0（L1前）: この言語役割とユースケースを設計前提に追加。作成時の言語選択/defaultLang並べ替え問題の修正範囲を確定する。
- L1: 通常/分割の表示統一を、日本語→英語と英語→日本語の両方向で実装・検証する。
- L2: UI言語をプロフィールへ移動し、新規作品/Flowの原文言語指定と既定言語の明示操作を追加する。
- L3: 手入力と一段落pasteの導線を整備し、章/全文の取り込みは対応付け試作→確認→実装の順に独立した単位で進める。
- H1/H2/H3: ヘルプとヘルパーはL1/L2と手動編集の実挙動を基準に整備する。未実装の全文取り込みを利用可能な操作として案内しない。L3の試作確認待ちでもヘルプ基盤は進められる。
- 原文言語の変更、中間訳からの再翻訳、訳独自の段落構造は後続。今回の計画で保存形式の変更を承認したとは扱わない。

## 受入確認

日本語UI/英語原文/日本語訳、英語UI/日本語原文/英語訳、原文のみ、欠落訳、意図した空訳、古い訳、手動と機械の混在を確認する。英語原文から日本語の縦書き・横書き訳への組版、同じ作品の異なる原文Flowも対象にする。
原稿取り込みでは同段落数で内容不一致、異なる段落数、CRLF/空行、章の途中、既存手動訳、編集中の原文変更、失敗時の全件保持、Undo/保存復元を検証する。
