## 原因と変更

- Home とリーズで一覧取得処理を共有していたが、取得結果と処理中の要求は共有していなかった。画面の再描画・往復ごとに Works、旧形式の Project／公開インデックス、各 Work の Release／edition_states を全件取得していた。
- 同じ認証セッション・表示言語の取得をまとめ、成功した一覧だけをメモリー内で30秒保持する。永続ストレージには保存しない。スペースによる絞り込みは利用側で毎回行う。
- 一覧を各画面に複製して渡す。認証セッション変更時は破棄し、無効化前に開始した応答が新しい一覧を上書きすることを防ぐ。最初の Home 描画が終了しても、同じ認証セッションのリーズは処理中の取得を引き継げる。
- 初回は Works が届き次第、Release／状態の取得を始める。最大6作品を同時に取得し、空いた枠から次の作品を取得する。旧形式の Project 取得や一つの遅い作品によって後続作品を一括で待たせない。全取得が成功するまで件数を確定しない。
- 手動の「更新」と取得失敗後の再試行は再取得する。発行、公開状態変更、版名・後継版の保存、アーカイブ・復元・廃棄の実行後は取得結果を無効化する。応答が途切れてサーバー側の成功が不明な場合も同様。別タブには無効化通知だけを送る。
- ダークテーマでもライト用背景を使っていたホバー／選択の色を、背景と文字色の組で定義した。リーズの操作ボタン、日時、確認ダイアログ、Home の操作メニューもテーマに従う。
- Home、最近の作業、編集中表示、リーズの表紙に1pxの枠を重ねる。白い表紙でも境界が見え、画像なしの枠も保つ。9:16、角丸なし、画像寸法は維持する。

保存形式、公開権限、版の内容・URL、ユーザー作品の公開状態は変更していない。
