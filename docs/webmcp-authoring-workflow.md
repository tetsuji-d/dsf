# WebMCP：新規プロジェクトから執筆・発行まで

2026-09-17。ユーザーが「ゼロからプロジェクトを立ち上げて書き上げて発行する」WebMCP機能拡張を希望。現在の5ツール（staging `43de14d`）から段階的に進める。保存仕様は既存のProject v6／FlowDocumentを維持する。

## 実装順と完了条件

| 工程 | 内容 | 完了条件・現在地 |
|---|---|---|
| 1 新規作成・執筆 | 新規作品、原文言語・縦横指定、見出し・段落追加、既存段落編集 | 今回ローカル実装。合成原稿＋Chrome実APIで新規作成→再許可→追加→Undoを確認。実Studioでのユーザー作品・クラウド保存は未検証。 |
| 2 制作対象・メタデータ | Flow間移動、作品タイトル・著者・説明、章構成、本文言語切替 | 未着手。正確なIDによる対象指定、変更前照合、Undo、保存完了の状態取得が必要。 |
| 3 画像・翻訳・仕上げ | 既存アセット一覧・画像配置・表紙指定、翻訳言語追加／入力、配置とプレビュー | 未着手。まず登録済みアセットIDで挿入。外部AIの生成画像受け渡しは別途設計。元画像・既存翻訳・段落紐づけを保持する。 |
| 4 発行準備 | Press検証、未翻訳・画像・フォント・容量の確認、DSF生成準備 | 未着手。現在の原稿revisionと言語・設定に対応する検証結果とプレビューを返す。処理ID・進捗・失敗理由を取得可能にする。 |
| 5 Horizon発行 | 非公開下書き、公開対象と設定の確認、発行、URL取得 | 未着手。編集と発行の許可を分離。承認は具体的な作品・snapshot・公開範囲・設定に結び付ける。変更後は検証し直す。再送でReleaseが重複しないことを確認する。 |

AIは内容を組み立てて構造化ツールを呼び、DSFが入力検証・原稿更新・組版・保存・発行を担う。AIモデル自体をDSFへ内蔵する変更ではない。画像生成や翻訳の能力は接続AIと利用者の素材に依存する。

## 工程1のツール

読み取り3ツールに対し、「原稿の作成・編集を許可」をオンにすると既存の取得・置換と次の3ツールを追加し、Studioでは計8ツールになる。

- `dsf_create_flow_project`: contextのworkToken、projectName、title、languageKey、writingModeを指定。原文言語は日本語固定にしない。縦書きが対応していない言語・不正値は作成前に拒否する。空のFlow原稿から開始する。
- `dsf_prepare_flow_append`: 現在のFlowの最終section末尾に追加する券を取得。原文言語でのみ使用可能。翻訳ビューで構造を増やさない。
- `dsf_append_flow_blocks`: 最新のappendTokenで見出し／段落を1〜20件追加。本文合計12,000 UTF-16 unitsまで。headingのlevelは1〜6、paragraphにlevelは指定しない。追加する新しい段落には改行を含められる。既存段落の全文置換では従来どおり既存改行を維持する。

追加位置とFlow全体のsnapshotを照合し、対象・言語・本文が変われば停止する。既存本文、翻訳、注釈、配置は変更しない。1回の追加を既存の1回のUndoで戻せる。同一引数の直前の再送は履歴を増やさない。異なる追記には新しい券が必要。券・応答履歴はタブのメモリ内だけに置く。

## 新規作成と保存

Studio既存の新規作成の初期化をUI／AIで共有する。AI経路は保存待ちを処理し、現在の作品をローカルの最近のプロジェクトへ退避してから切り替える。退避失敗、待機中の編集、対象切替、許可解除、呼び出し取消で作成を中止する。旧作品のクラウドデータや公開Releaseは削除しない。

新作品は新しいWorkと独立したローカル保存IDで始める。Project v6、言語、タイトルと空Flowを設定し、通常の自動保存へ接続する。作成完了はクラウド保存完了を意味しない。新規作成は別作品への切替なのでUndoで旧作品には戻らず、退避した作品を最近のプロジェクトから開く。

作品切替で従来のAI許可を失効させる。作成応答に`permissionReset:true`と再許可の案内を返す。現段階ではユーザーが新作品で一度許可し直す。最終的な制作セッションを継続する許可の設計は、作品単位の権限を保って後続単位で扱う。

## 検証と未対応

`npm run verify:editor-authoring-tools`：英語原文／日本語縦書き、追加の境界値、既存内容保持、古い券、再送、Undo相当の復元、新規作成の競合・取消・バックアップ失敗を検証。

`studio-webmcp-write.html?authoring=1`：本番と同じツール登録・共通作成境界・履歴を使う合成原稿。バックアップはメモリのみ。Chrome実APIで8ツール登録、新規英語作品、切替時の解除、再許可、見出しと2段落追加、再送で重複なし、Undoを確認。Studio本体の認証・IndexedDB・クラウド保存や外部AIがツールを自動選択することの検証とは区別する。

まだ一度の依頼だけで公開まで完了する状態ではない。画像・翻訳・章管理・保存結果・発行準備／発行は上記順序で追加する。コミット・デプロイは別途依頼時に行う。
