# WebMCP：新規プロジェクトから執筆・発行まで

2026-09-17。ユーザーが「ゼロからプロジェクトを立ち上げて書き上げて発行する」WebMCP機能拡張を希望。現在の5ツール（staging `43de14d`）から段階的に進める。保存仕様は既存のProject v6／FlowDocumentを維持する。

## 実装順と完了条件

| 工程 | 内容 | 完了条件・現在地 |
|---|---|---|
| 1 新規作成・執筆 | 新規作品、原文言語・縦横指定、見出し・段落追加、既存段落編集 | staging `2b03f40`。合成原稿＋Chrome実APIで確認済み。ユーザーからClaude in Chromeで新規作品「潮騒の図書館」、18ブロック・4ページ作成とローカル保存の成功報告あり。クラウド保存の完了確認とは区別する。 |
| 2 制作対象・メタデータ | Flow間移動、作品タイトル・著者・説明、章構成、本文言語切替 | 未着手。正確なIDによる対象指定、変更前照合、Undo、保存完了の状態取得が必要。 |
| 3 画像・翻訳・仕上げ | 既存アセット一覧・画像配置・表紙指定、翻訳言語追加／入力、配置とプレビュー | 画像部分を先行実装（ローカル）：素材一覧・画像ページ追加・UI画像貼り付け。翻訳と詳細配置は未着手。登録済みアセットIDで挿入。外部AIの生成画像受け渡しは別途設計。元画像・既存翻訳・段落紐づけを保持する。 |
| 4 発行準備 | Press検証、未翻訳・画像・フォント・容量の確認、DSF生成準備 | 未着手。現在の原稿revisionと言語・設定に対応する検証結果とプレビューを返す。処理ID・進捗・失敗理由を取得可能にする。 |
| 5 Horizon発行 | 非公開下書き、公開対象と設定の確認、発行、URL取得 | 未着手。編集と発行の許可を分離。承認は具体的な作品・snapshot・公開範囲・設定に結び付ける。変更後は検証し直す。再送でReleaseが重複しないことを確認する。 |

AIは内容を組み立てて構造化ツールを呼び、DSFが入力検証・原稿更新・組版・保存・発行を担う。AIモデル自体をDSFへ内蔵する変更ではない。画像生成や翻訳の能力は接続AIと利用者の素材に依存する。

## 工程1のツール

工程1では読み取り3＋書き込み側5の計8ツール。画像対応時点では読み取り4、編集許可時は計12ツール。作品構成の読み取り追加後は読み取り5、編集許可時は計13ツール。「AI連携」をオンにし、「AIに許可する操作」で「閲覧・編集」を選んで使用する。

- `dsf_create_flow_project`: contextのworkToken、projectName、title、languageKey、writingModeを指定。原文言語は日本語固定にしない。縦書きが対応していない言語・不正値は作成前に拒否する。空のFlow原稿から開始する。
- `dsf_prepare_flow_append`: 現在のFlowの最終section末尾に追加する券を取得。原文言語でのみ使用可能。翻訳ビューで構造を増やさない。
- `dsf_append_flow_blocks`: 最新のappendTokenで見出し／段落を1〜20件追加。本文合計12,000 UTF-16 unitsまで。headingのlevelは1〜6、paragraphにlevelは指定しない。追加する新しい段落には改行を含められる。既存段落の全文置換では従来どおり既存改行を維持する。

追加位置とFlow全体のsnapshotを照合し、対象・言語・本文が変われば停止する。既存本文、翻訳、注釈、配置は変更しない。1回の追加を既存の1回のUndoで戻せる。同一引数の直前の再送は履歴を増やさない。異なる追記には新しい券が必要。券・応答履歴はタブのメモリ内だけに置く。

## 新規作成と保存

Studio既存の新規作成の初期化をUI／AIで共有する。AI経路は保存待ちを処理し、現在の作品をローカルの最近のプロジェクトへ退避してから切り替える。退避失敗、待機中の編集、対象切替、許可解除、呼び出し取消で作成を中止する。旧作品のクラウドデータや公開Releaseは削除しない。

新作品は新しいWorkと独立したローカル保存IDで始める。Project v6、言語、タイトルと空Flowを設定し、通常の自動保存へ接続する。作成完了はクラウド保存完了を意味しない。新規作成は別作品への切替なのでUndoで旧作品には戻らず、退避した作品を最近のプロジェクトから開く。

AI連携のオン／オフと閲覧・編集範囲はブラウザーのlocalStorageに保持する（初期値はオフ・閲覧のみ）。作品切替では実行中処理と旧トークンを失効させ、新しい作品の状態反映後に同じ許可範囲で再登録する。作成応答は`workTokenExpired:true`を返す。AIは新しいcontextを取得してから操作を続ける。エディター外／pagehideでは登録を停止し、戻ると再開する。明示的なオフや閲覧のみに戻す操作は保存し、同一originの他タブへも反映する。設定保存失敗時はタブ内のみ保持と表示する。発行の許可は追加しない。

## 検証と未対応

`npm run verify:editor-authoring-tools`：英語原文／日本語縦書き、追加の境界値、既存内容保持、古い券、再送、Undo相当の復元、新規作成の競合・取消・バックアップ失敗を検証。

`studio-webmcp-write.html?authoring=1`：本番と同じツール登録・共通作成境界・履歴を使う合成原稿。バックアップはメモリのみ。当初の検証ではChrome実APIで8ツール登録、新規英語作品、切替時の解除、再許可、見出しと2段落追加、再送で重複なし、Undoを確認。Studio本体の認証・IndexedDB・クラウド保存や外部AIがツールを自動選択することの検証とは区別する。

まだ一度の依頼だけで公開まで完了する状態ではない。画像の基本対応は以下の範囲で実装。翻訳・章管理・保存結果・発行準備／発行は後続で追加する。コミット・デプロイは別途依頼時に行う。


## 画像ページとクリップボード（2026-09-17 ローカル実装）

- UI：画像自体をコピーし、エディターのページ上でCtrl+V／Macは⌘V。またはアセットの「画像を貼り付けてページ追加」。画像URLやHTMLからの自動取得は行わない。画像ファイルのアップロード／ドロップは既存どおり素材登録のみ。
- 貼り付けは選択中のページ／Flow全体／見開きの後ろへ新しい画像ページを追加。本文や選択画像を置換しない。通常の文字貼り付けは既存経路を維持する。
- `prepareAuthoringImage`でクライアントWebP変換（品質0.9、長辺最大7680px、変換後25MB以内）とサムネイルを生成。素材＋ページを一度の履歴更新で追加し、Undo／Redoと通常の自動保存に接続。変換中やクリップボード取得中の作品・本文・素材・選択・言語変更は中止する。
- WebMCPはクリップボードを読まない。画像生成もしない。取り込んだ素材の配置に加え、下記の画像データ受け取りにも対応する。
- `dsf_list_image_assets(workToken, offset?)`：20件ずつ素材ID・名前・寸法・バイト数を返す。画像URL／バイト列を応答へ含めない。
- `dsf_prepare_image_page(workToken, assetId, position)`：`start`／`end`は作品全体、`before`／`after`は選択中Flow全体または見開きの境界。挿入先の前後ID・現在言語・imageTokenを返す。Flow文書・翻訳を分割しない。
- `dsf_add_image_page(workToken, imageToken)`：最新の準備内容を照合して追加。1回のUndo、直前の同一要求再送は重複しない。許可解除・作品切替で券を破棄。発行はしない。

AIへの依頼例：『WebMCPで画像素材一覧を取得し、「表紙.png」を使って作品の先頭に画像ページを追加してください。本文は変更しないでください。』画像をまだ取り込んでいない場合は、アセットへアップロードしてから依頼する。

検証：`npm run verify:editor-image-tools`、既存の3つのWebMCP単体検証、stagingビルド。`scripts/fixtures/studio-image-paste-ui.html`の合成原稿で、ChromeのCtrl+Vとボタン貼り付け、PNG→WebPの実バイト署名（RIFF/WEBP）、Undo、実`document.modelContext`から先頭への追加・再送を確認。画像データ受け取り追加後、検証ページは新規作品作成を提供しないため11ツール、本体は12ツール。


## AI生成画像の直接受け取り（2026-09-17 ローカル実装）

`dsf_prepare_image_import(workToken, name, mimeType, dataBase64, position)`を編集許可時のみ提供する。

1. AIクライアントが生成した画像、またはユーザーから渡された実画像のバイト列を取得する。
2. `dataBase64`に画像のBase64本体（data:接頭辞なし）、`mimeType`に`image/png`／`image/jpeg`／`image/webp`を指定する。`position`は既存画像と同じ`start`／`end`／`before`／`after`。
3. DSFがバイト署名と画像デコードを確認し、既存の`prepareAuthoringImage`でWebP・サムネイルを生成。名前・変換後寸法・容量・前後のブロックID・`imageToken`を返す。本文、ページ、素材一覧はこの時点で変わらない。
4. `dsf_add_image_page(workToken, imageToken)`で素材登録とページ追加を1回のUndo単位として適用。通常の自動保存へ接続する。再送は重複追加しない。

入力上限は1画像8MiB（Base64は最大11,184,812文字）、各辺16,384px、4,000万画素。AI／ブラウザ側がより小さな引数上限を設ける場合はそちらが優先される。変換後は既存の長辺7,680px・25MiB上限を使う。外部URLの取得、SVG、クリップボード読み取り、AI画像生成そのものは含めない。AI側が実画像を取得してツール引数へ渡せなければ、UIアップロード／貼り付けへ案内する。Base64を文章として捏造して渡さない。

準備した画像は一時領域だけに保持し、5分で期限切れになる。再準備・許可解除・タブ終了で破棄。変換中に許可・作品・本文・素材・選択・言語が変わった場合も追加を中止する。素材ID／画像URL／画像バイトは準備の応答に含めない。

`npm run verify:editor-image-import`で入力検証、変換オプション、準備段階の非変更、追加／Undo／再送、競合・取消と一時画像の破棄を検証する。ブラウザ検証ページでは合成PNGを実WebMCPに渡す。外部AI製品の画像生成からの自動転送は、DSF側の受け取り機能と別途実機確認する。

## 制作ルール・作品構成の読み取り（2026-09-18）

`dsf_get_editor_context` は共通制作ガイドを返す。`dsf_get_book_composition({workToken, languageKey, offset?})` で言語ごとの組版済みページを最大50件取得し、`nextOffset` で続きを取得する。読み取り中に編集した場合は最初から取得し直す。全13ツール（読み取りのみ5ツール）。

- 総ページ数、ページ送り方向／綴じ方向、C1〜C4と本文の位置、元のblock/group ID、Flowページ番号、縦横書き、原文代替表示、構成上の問題を返す。
- 表紙ありの電子版は2以上の偶数。4の倍数は冊子印刷の条件で、印刷白紙の見積りは作品の本文を変更しない。表紙は位置で決まり、Flow本文が表紙位置にある場合は意図の確認を促す。
- 読み取りは新規組版を起動しない。現在の原稿・設定に一致するキャッシュのみを利用し、未生成・編集中はページ数をnullとする。原文代替は翻訳完成とみなさない。
- readyはエディターの組版状態だけを意味する。Pressの検証完了や発行可能性を保証しない。
- 新規作成・本文追加・画像挿入後には構成の再確認を案内する。表紙設定の変更や白紙挿入の新規ツールは追加しない。
- ヘルプの「表紙・裏表紙の構成」「電子版のページ数・言語」「冊子印刷と補完白紙」「固定レイアウトと画像素材」「AIによる制作の確認事項」とAIガイドは `js/authoring-guide.js` を共通の説明元とする。日本語／英語で検索できる。

AIへの依頼例：『まず編集状態と日本語の作品構成を取得してください。表紙C1、内表紙C2、本文、内裏表紙C3、裏表紙C4が意図どおりか確認し、変更後にも構成を再取得してください。未生成のページ数は推測せず未確定と報告してください。』

DSP/DSF保存形式、Firestore、原稿本文、発行権限は変更しない。

検証：`verify:editor-book-composition`、既存の読み取り／編集／新規作成／画像検証とstagingビルドが通過。Chromeの実`document.modelContext`で合成14ページ・16ページ・未生成の読み取り、Studio本体で実組版済み2ページの構成取得、日英ヘルプの検索・表示を確認。AIモデルが案内どおり制作するかの外部AI対話試験とは区別する。


## AI設定とUI言語更新（2026-09-18）

プロフィールは「AI連携」のトグル＋「閲覧のみ／閲覧・編集」の選択へ整理。接続の詳細は折りたたみ、設定保存範囲を明記する。localStorageには設定2項目のみを保存し、原稿やwork/edit/imageトークンは保存しない。旧登録の遅延応答が新作品の登録を解除しないよう、応答時にも接続世代を照合する。

UI言語を変更すると、既存キャンバスの本文／画像ラベル、通常／分割コントロール、Flowページの編集状態をその場で更新する。本文や生成ページのDOMを作り直さず、選択・キャレット・拡大率・スクロールを維持する。

検証：設定の初期値・保存／復元・明示的オフ・閲覧モードへの変更・作品切替・エディター退出／復帰・pagehide／pageshow・保存失敗を自動確認。Chromeの実APIでは合成原稿で新規作品作成後に再許可せず見出しと2段落を追記でき、再読み込み後も閲覧・編集設定が復元されることを確認。Studioでは言語切替でNormal／Split、Image／Flow text、Flow原稿の位置表示を更新する。
