## 第1段階: 表紙サムネイル

既定アプリ／公開権限／ファイルアクセス権を変更しない。

既存DSFの画像表紙を読むnative部品・検証コードは
[開発用README](../native/windows-preview/README.md)に記録。
検証専用拡張子でのOS連携に続き、承認を受けてこの開発PCの`.dsp`／`.dsf`へ常設済み。
通常ローカルフォルダーでの表紙表示は確認済み。OneDrive内の取得待ちと一般配布は未解決。

### 承認済みDSPの保存内容

DSPの現在の画像素材だけでは、表紙の文字・装飾・トリミングまで再現できるとは限らない。
2026-10-03にArchitectが任意の表紙PNG同梱を承認した。次の保存拡張を実装。

- DSP保存時に任意の`preview/cover.png`を追加する。
- `preview/cover.json`に言語・寸法と、保存するproject.json／PNGそれぞれのSHA-256を記録する。
- 原稿の保存snapshotと同じrevision・言語・C1を描画した画像だけを入れる。
- 本文、作者、画像原本、project.jsonの編集データ構造は変更しない。
- 既存のReaderが未知entryを無視できることを回帰検証する。
- snapshotが作れない場合は追加を省略して原稿保存を成功させる。前回の古い表紙を流用しない。
- 古いDSPや未対応の表紙は種類別アイコン。原稿を自動再保存／変換しない。
- 表紙の縮小画像も配布ファイルに入ることを保存仕様へ明記する。

既存の固定ページrendererを使い、既定言語の先頭ページを合成する。Flow原稿から始まる作品や
描画順が未定義の古い吹き出し表紙は現時点で省略する。1.5秒を超える描画も省略し、原稿保存を優先する。
生成中のproject session／編集状態の変化を監視し、混在した画像を追加しない。
この拡張はローカルDSPのみで、クラウド原稿schema／DSF配布形式／Horizonには追加しない。

実画面でDSPをダウンロード保存、PNGの寸法・hashを照合、別browser contextから再読込した。
表紙entryがある版と除いた旧形式版のauthoring読込結果も一致した。保存した実DSPをnative COMでも確認。

隔離機能と既存の関連付けを維持し、一時登録は解除済み。

### 合格条件

原本hash不変、表紙一致、非対応時の通常アイコン、原稿保存を妨げないこと、Explorer実表示、
新規導入／更新／解除、他アプリの関連付け維持、WebP codecの新規端末での再現性。
ブラウザー内のサムネイルや開発用PNG生成だけでは合格にしない。

## 第2段階: 内容プレビュー

第1段階のOS連携と配布・解除を確定後、IPreviewHandlerの読取専用画面を追加する。
ページ送り、ページ番号、必要に応じた言語選択を提供し、編集・保存・Horizon発行は行わない。

- DSF: 既存Viewerの固定レイアウト解釈と合わせる。画像だけでなくfixedText／同梱fontも対象。
- DSP: 確定済み描画が無い編集原稿をどの範囲まで再現するか先に検証する。
  「素材画像を順に出す」方式で本文・レイヤーを省略しない。
- OS内でWebView2等を使う場合も信頼済みのローカル表示コードだけを実行し、
  原稿中のHTML、外部URL、認証、共有設定、ネットワークを接続しない。
- ファイル全体の無条件展開や一括描画を避け、表示ページだけを処理し、閉じたら資源を解放する。
- Viewerと先頭／中間／末尾、固定本文、画像、縦横、言語、異常ファイルを比較する。
