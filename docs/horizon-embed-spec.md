# Horizon 埋め込み仕様案

作成日: 2026-10-25。状態: 初期実装をstagingで検証中。本番未反映。
2026-10-25の実装指示に基づく初期仕様。実環境の確認範囲・未確認範囲は検証記録を参照。
版・URL・公開状態は [版の合意仕様](horizon-editions-spec.md) を継承する。
実装順と検証条件は [実装計画](horizon-embed-implementation-plan.md) を参照。

## 1. 目的と合意済み要件

### 2026-10-27 初期表示と読書開始（下記の本アイコン案を更新）

- 初期表示は表紙と中央の `Open Read.`。タイトル・Horizonロゴ・ページ送り・ページバーも最初から表示する。初期状態では自動非表示にしない。
- 初回のOpen Read、順方向スワイプ、ページ送り、バー選択で本文と読書用フォントを取得する。最初の操作を保持し、読み込み完了後に一度だけ実行する。読み込み中も表紙と進捗文言を残す。
- 初期通信は公開状態・表紙・版の小さなcontent indexに限定する（UI用フォントは別）。本文言語manifest・読書用フォント・閲覧計測の開始は初回操作後。ロゴの別タブ移動と全画面操作だけでは本文取得を始めない。
- Horizonロゴは左、ページ送りは中央、全画面は右で同じ下端に揃える。ページバーはこの操作列の一段上（下端から58px）に配置。線は3px、操作範囲は44pxでボタンと分離する。バー幅・色・読書開始後のサムネイルは既定仕様を継承。
- 読書開始後は最後の操作から約3秒でタイトル・ロゴ・操作列・バーを隠す。中央タップまたはTab操作で再表示する。メニュー操作・キーボードフォーカス・バー操作中は隠さない。
- 初回の本文読み込みが失敗した場合は、表紙待機を解除して既存Readerのエラーと再試行導線を表示する。

### 2026-10-27 操作アイコン・ページバー更新

- 読むボタンは青い枠・背景を使わず、白い本の線画とドロップシャドウ。閉じた本→半開き→開いた本の3コマを表示し、RTLでは開く方向を反転する。動きを減らす設定では開いた本の静止画にする。読み上げ名とキーボードフォーカスは保持する。
- 埋め込みページバーは画面最下部の中央。表示中の1ページ幅の90%（左右それぞれ約5%余白）とし、見開きでも2ページ幅には広げない。
- 線は3px、未読は黒、既読・現在ページは鮮やかな赤。ホバー位置までの未読部分を灰色で予告し、その位置の9:16サムネイルを表示する。WebP・固定テキストを共通のReader描画で扱う。
- ホバーだけではページを移動しない。クリック・タッチ・ドラッグ・キーボードで選択する。タッチ操作範囲は44pxを保ち、中央のページ送りボタンとは重ならない配置にする。
- 表示調整のみ。公開状態・ドメイン制限・閲覧集計・版の内容とURLを変更しない。

- スマホで読める9:16固定ページを、外部サイト内でも広告なしで届ける。
- WebP・固定テキスト・多言語は通常Readerと同じ版・同じ描画品質を使う。本文の再組版や解像度の意図的な低下は行わない。
- ドメイン制限は出版者が選べるオプションとする。
- 埋め込みの読み込みだけでviewを増やさない。
- 埋め込みを禁止・制限しても、公開／限定公開の通常リンクからは閲覧できる。
- 実装・staging反映までを対象とする。mainマージ・本番反映は対象外。

## 2. 初期リリースの提案

### Readerの使い方

最初は表紙、タイトル、版名、出版者、「読む」、「Readerで開く」を表示する。表紙なしでも9:16枠とプレースホルダーを保つ。
「読む」を押してから本文・必要なフォントを取得し、既存Readerの描画処理で表示する。自動再生・自動ページ送りは提供しない。
表紙と必要最小限の案内取得は発生するが、viewにはしない。全ページや全言語の先読みもしない。

本文表示中はページ送り・戻り、現在ページ／総ページ、言語、拡大、Readerで開くを提供する。
広告、関連作品のおすすめ、制作操作、ログイン要求、レビュー投稿等を埋め込みUIへ持ち込まない。
作品本文内のリンクは版の表現として保持する。親サイトを勝手に遷移させず、外部への移動を読者の操作で行う。

PCでも縦ページを基本とし、外側のUIだけを画面に合わせる。9:16は本文の比率であり、操作バー込みのiframe全体には強制しない。
生成コードは幅100%・最大幅約480pxを既定とし、本文の9:16領域に操作欄を加えた高さを確保する。
高さの低い横画面では本文を収め、本文を横に引き伸ばさない。読みにくい小さな枠では「Readerで開く」を明確に示す。
操作領域はスマホで44px以上。キーボード、フォーカス表示、ライト／ダーク、日本語／英語を用意する。
全画面化できない端末や埋め込み元の制約下では、通常Readerへのリンクを代替にする。

### リーズの設定

各版の「共有・埋め込み」から通常URL、埋め込み設定、コードのコピー、表示見本を開く。
通常URL欄と埋め込みコード欄を分け、コードのコピーでは公開状態を変えない。

| 設定 | 動作 |
|---|---|
| 埋め込みを許可しない（初期値案） | 通常リンクは閲覧可。外部iframeでは閲覧不可 |
| すべてのサイトに許可 | ドメイン登録なしで埋め込み可 |
| 指定したサイトだけに許可 | 登録サイトのみ埋め込み可 |

既存版と新規版の初期値は「許可しない」とする案。出版者の操作で有効化する。
第二版へ設定を自動継承しない。将来の「設定をコピー」も明示操作とする。
非公開で設定を準備できるが、「公開／限定公開にすると有効」と表示し、埋め込み可能と誤認させない。
アーカイブ中は設定を保持して無効化。復元先は既存仕様どおり非公開。廃棄後は再有効化不可。
限定公開では「埋め込み先の訪問者が閲覧・リンク共有できます」と説明する。

### 許可サイトの入力

初期版はHTTPSの完全一致ホスト、最大20件、標準443ポートに限定する案。
`example.jp` は `https://example.jp` として正規化し、保存前に対象を表示する。
`example.jp` と `www.example.jp`、他のサブドメインは別登録。ワイルドカード・パス単位指定・任意ポートは初期対象外。
URLのユーザー情報、パス（末尾 / を除く）、query、fragment、改行、IPアドレス等の不適切な入力は拒否する。
国際化ドメインはURLパーサーで正規化し、重複を除去。ローカル試験用HTTP許可は本番設定と分ける。
サイト作成サービスがiframeを多重化する場合は途中の親ドメインも許可が必要になるため、設定画面で説明する。

## 3. URL・公開状態・ドメイン制限

### Studioの埋め込み操作（2026-10-25更新）

- リーズのURL欄は、末尾を表示するURL、URLコピーアイコン、`</>`埋め込みアイコンを横並びにする。埋め込みアイコンには対象タイトルを含む読み上げ名と「埋め込み」のツールチップを付ける。
- 設定・コード・表示見本は専用モーダルに集約。タイトル、版名、公開状態を示し、非公開/アーカイブは現在表示されないことを案内する。
- 許可ドメイン欄は「指定サイトのみ」で表示。未保存の表示を付け、未保存中/埋め込みoff中のコードコピーボタンは無効。設定保存に成功した場合だけ保存済みへ更新する。
- PCは中央モーダル、スマホ縦/横は全画面、内部スクロールと固定ヘッダー。閉じる/ESC/背景クリックに対応。未保存なら破棄確認を表示し、Tab移動をモーダル内に保つ。閉じた後は元のボタンへフォーカスを戻し、一覧の開閉状態を保持する。
- 表示見本は折りたたみ、9:16・角丸なし・欠損時の枠を維持。これはローカル見本であり、掲載先の許可判定ではない。
- 閲覧数はモーダルから分離し、各行の「閲覧数」で確認・更新する。版の設定とも別の折りたたみにする。
- 保存方式・公開状態・版本文・URL・閲覧数の定義は変更しない。認証/画面セッション終了時には開いたモーダルを破棄する。

通常URLは既存の `/viewer?edition={editionId}`。埋め込み専用URL案は `/embed/{editionId}`。
どちらも同じ不変Releaseを参照する。公開ポリシーの変更で本文・版ID・URLは変わらない。
古いwork/project URLは既存の固定bindingを維持し、埋め込みコードの新規生成には確定したeditionIdを使う。
版identityが確定していない旧データは、移行前に埋め込みを提供しない。

| 版の状態 | 通常リンク | 許可されたサイトでの埋め込み |
|---|---|---|
| 公開 | 閲覧可・Horizon掲載 | 設定が有効なら可 |
| 限定公開 | 閲覧可・Horizon掲載なし | 設定が有効なら可 |
| 非公開／アーカイブ／廃棄／期限切れ／運営停止 | 既存の終了案内 | 本文は提供しない |

非公開を埋め込み設定で公開扱いにしない。旧版から後継版へ本文を自動で差し替えず、既存仕様に従って通常Readerに案内を置く。

### ブラウザーによる制限

埋め込みHTMLのHTTP応答に `Content-Security-Policy: frame-ancestors ...` を付ける。
「すべて許可」は `https:`、指定サイトのみは検証済みoriginの列、禁止は `'none'` を基本とする。
Refererやqueryの自己申告を認可に使わない。設定取得失敗や未知の版は許可へ倒さない。
通常Readerは外部からのフレーム表示を禁止し、通常URLをiframeへ入れる迂回を防ぐ。トップレベルで開く閲覧は維持する。
`/viewer`、`/viewer.html`、旧URL、静的シェル、別ホスト名、サービスワーカー経由も含め、別入口からの迂回を検証する。
内部プレビューの同一origin iframeが必要なら `'self'` を検討するが、外部祖先からの多重iframeは許可しない。

`frame-ancestors` はHTTPヘッダーで指定し、metaでは指定しない。多重iframeのすべての祖先が判定対象になる。[MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)
Pages Functionsの応答には `_headers` が適用されないため、動的応答側でも明示する。[Cloudflare](https://developers.cloudflare.com/pages/configuration/headers/)

拒否されたiframe内ではDSFの案内を表示できないことがある。コピーするコードにはiframeの外に常設の「DSF Readerで読む」リンクを含める。
許可判定HTMLと状態確認応答は `no-store`、サービスワーカーの保存対象外とし、不変本文assetのキャッシュと分離する。
表示開始時・バックグラウンドから復帰時・閲覧中60秒ごとに公開状態と設定revisionを再確認する案。
変更時は再検証し、許可できなければ本文表示を終了する。確認失敗時は再試行案内にして読書の継続を保留する。
通常の定期確認・タブ復帰時の確認は、応答待ちの間も直前に許可されたページを表示し続け、点滅させない。閲覧不可・通信失敗が確定したら本文と操作を隠す。一度隠した後の再試行中は隠したままとし、許可を再確認できた場合だけ復帰する。
既に読み込んだHTMLには新CSPを後付けできないため、ポリシーrevision変更時には埋め込み文書を再読込して再判定する。
これらは通常ブラウザーでの埋め込み制御であり、コピー済み画像や第三者による再配信を防ぐDRMではない。取得済みassetを回収する保証もしない。

## 4. viewの仕様案

### 数える条件

埋め込みでは次をすべて満たした後、1回の閲覧として受理する。

1. 「読む」を読者自身が押した。
2. 対象版の本文ページの描画が成功し、現在も閲覧可能である。
3. タブが前面で本文領域の50%以上が画面内にある状態で、連続5秒経過するか、読者のページ送り／戻りで別の本文ページを表示した。

初期ページへの自動移動、しおり復元、言語切替、通信再試行、画像・フォント読み込み、拡大ボタンだけではviewを確定しない。
画面外・背景タブ・エラー中は時間を進めず、連続時間をリセットする。5秒と50%はDSF用の初期基準案であり、他社の基準を正本にしない。
通常リンクのReaderは「読む」を追加せず、本文表示後に同じ可視時間／ページ操作条件を適用する。通常アクセスの読書開始に余分な操作を増やさない。
IntersectionObserver等は表示状態の近似であり、人の注視や悪意あるCSSによる隠蔽を完全には証明できない。外部originのiframe・Safariで実測し、可視性不明の場合は時間だけの確定を避ける。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)

### 重複・不正・表示名称

- 同一版・同一計測セッションは1view。再読込・同時送信・タイムアウト後の再送でもserver側で一度だけ確定する。
- セッションは匿名のランダムIDを使用。初期案は30分の固定計測窓とし、再読込でも窓を更新しない。期限後に再度条件を満たす閲覧は別viewになり得る。
- タブ内保存を利用するが、第三者ストレージ禁止時はメモリへ縮退する。その場合の再読込重複や、別サイト・別ブラウザー間の同一人物判定は保証しない。閲覧数を「読者人数」と呼ばない。
- 通常Reader／埋め込みの流入区分を持つ。別タブでReaderを開いた場合のセッション統合は初期対象外であり、両方で条件を満たせば別viewになり得る。
- ownerプレビュー、ローカルファイル、Studioの表示見本、テスト環境のイベントを本番閲覧数に含めない。匿名の出版者本人まで自動識別できるとは表示しない。
- eventIdの冪等性だけでなく、版・セッション・計測窓の組でserver側重複排除を行う。短期のランダムな不透明計測ticket（serverの保存値と照合）、受付上限、期限・公開状態の再確認を組み合わせる。
- ticketは閲覧許可証や人間判定ではない。公開URLからticketを取得して反復送信する不正に備え、発行・集計両方を制限する。IP単独で人数を数えない。
- 指標送信失敗で読書は止めない。同じticket/keyで上限付き再送し、長期オフライン分は初期版では後日水増ししない。
- 初期版では表紙ロードごとの「表示回数」を永続収集しない。不要な書込と数字の混同を避け、必要になった段階で閲覧数とは別に追加する。
- 既存の `page_view` は「表示したページ数」であり既読の証明ではない。最後に飛んだだけの `read_complete` も「読了」と断定しない。新指標では最終ページ到達として区別し、読了率は別途設計する。

匿名閲覧で完全な不正防止は保証できない。初期目標は通常のHP更新・複数iframe・再送による過剰計上を抑えること。
refererは保存する場合でもoriginだけとし、外部サイトのパス・query、端末指紋を新指標へ保存しない。
重複排除情報は計測窓の終了から30日後にTTL削除対象とする。受付制限情報は1日後に削除対象とする。TTLの物理削除は非同期。長期表示は版・日・流入区分の集計を使用する。

## 5. 保存境界の提案

保存契約は `docs/data-model.md` の2026-10-25追記に記録する。ZIP形式は変更しない。

- `edition_states/{releaseId}` に可変の埋め込み設定案 `embedPolicy: { version: 1, mode: 'off' | 'any' | 'allowlist', allowedOrigins: [...] }` を置く。未設定はoff。
- 所有者用設定は既存認証APIのrevision・requestId・所有権確認で更新。Release／公開snapshot本文は変更しない。
- 匿名で設定原本を取得できる一覧APIは作らない。公開入口はserverが版状態と設定を読んで応答を作る。許可ドメインはCSPに出るため秘密情報にはできない。
- 新しい指標は `schemaVersion: 2` 相当の別契約としてserver受付・集計する。既存 `metric_events` のload由来viewと無条件に合算しない。
- 計測用のserver-only保存面、日次集計、期限削除を使用する。新しい署名鍵は不要で、ticketをserverで照合する。新collectionは既存Rulesのdefault denyによりclientから読み書きできない。
- DSF/DSP ZIP、本文・フォント・画像のハッシュ、不変URLの仕様は変更しない。

## 6. 初期対象外

自動再生、第三者広告、親サイトからの自由なReader操作API、ワイルドカードドメイン、サイト横断の人物追跡、読了保証、決済・会員制の埋め込みは含めない。
ページ送りアニメーションの高度化よりも、スマホの読みやすさ、正常な公開制御、計測の一貫性を優先する。
