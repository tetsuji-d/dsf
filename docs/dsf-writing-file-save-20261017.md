# Writing ファイル保存の導線

- Reader終了時とWritingの保存パネルで、開いたDSFRのファイル名を維持する。
- 旧DSFはDSFRへ拡張子を移行。元名が分からない下書きは作品名を使う。共有用は編集用と混同しないよう `-shared` を付ける。
- 作成後、同じFileを `navigator.canShare({files})` で判定する。対応時は「保存・共有」ボタンのクリックで直接 `navigator.share` を呼ぶ。ZIP生成中のawaitを跨いで共有を起動しない。
- 非対応時は通常ダウンロード。共有失敗時もダウンロードを選べる。キャンセル時に勝手にダウンロードしない。
- ダウンロード導線は「ダウンロードで保存」。共有対応時には「共有メニューが使えない場合はこちら」と補足する。
- iPhoneでは「“ファイル”に保存」、上書きしたい場合は同じフォルダ・同じ名前で置き換えるよう案内する。元ファイルへの書き込み権限を取得する変更ではない。
- 共有完了やダウンロードのクリックでは、ファイル保存の完了と見なさない。保存後にユーザーが確認ボタンを押してReaderへ戻る／保存済みとして扱う。途中キャンセルはWritingを維持。
- パッケージ形式・原本・クラウド保存先・権限は変更しない。

検証:
- `node scripts/writing-w1/verify-file-save.mjs`: 名前・bytes・共有開始タイミング、模擬OS共有の成功／キャンセル／失敗／非対応、明示確認だけで完了する境界。
- ブラウザー390×844: 筆記→終了確認→生成→ダウンロード→書き込み継続→再度保存確認→明示確認→Reader復帰。通常の保存パネルは日本語、終了確認は英語でも確認。横スクロールなし。
- ブラウザーで保存した `sample.dsfr` を同スクリプトの引数として再読込し、筆跡1個と原本8entry不変を確認。
- ステージング用ビルド・`verify-staging.mjs`の配布モジュール／キャッシュ整合性を確認。
- iPhone固有の共有シート、Filesでの置き換えは実機での確認が必要。
