# DSP・DSFのインストール確認

対象: 2026-10-03 / staging / 実装コミット `ecb3b60`

## 確認するもの

「ファイルが開くこと」「専用アイコンになること」「作品の表紙が表示されること」は別です。
今回確認するのは最初の2つです。表紙サムネイルは今回の対象ではありません。

検証には同梱の `sample.dsp` と `sample.dsf` を使います。ログインや実際の原稿は不要です。
手動でアイコンを指定すると自動登録の検証にならないので、設定は変更しないでください。

## Macをお持ちの方へ（目安10分）

1. ZIPを展開し、Finderにある2つのファイルが現在どう表示されるか確認します。
2. Chromeで https://staging.dsf-studio.pages.dev/studio?room=home を開きます。
3. アドレスバーのインストールボタン、またはメニューのアプリとしてインストールする項目から追加します。名前は **DSF Studio (staging)** です。
4. Finderでファイルを右クリックし「このアプリケーションで開く」に追加したDSF Studioがあるか確認します。既定のアプリを変更する必要はありません。
5. `sample.dsp` をDSF Studioで開き、受け取り画面の「開く」を押します。エディターに青い本のマークが1ページ表示されれば成功です。
6. `sample.dsf` も同様に開き、Viewerに同じマークが表示されるか確認します。
7. アプリのウィンドウをすべて閉じ、再度ファイルから開けるか確認します。
8. Finderに戻り、DSPが緑・DSFが青のアイコンになったか確認します。同梱のPNGはデザインの見本です。白いまま／アプリアイコンと共通でも、そのまま結果をお知らせください。

アプリが一覧にない場合は、Studioの「DSPファイルを開く」、Viewer https://staging.dsf-studio.pages.dev/viewer の「ファイルを選択」から試してください。この場合は「アプリ内からのみ開けた」と記録します。

Safariの「Dockに追加」を試す場合は、Chromeの結果と分けて記録してください。同じファイル関連付けができることは前提にしません。

## Androidタブレットでの確認

1. Chromeで上のStudioを開き、メニューからホーム画面への追加／インストールを行います。
2. 追加したアプリを開き、アプリ内の「DSPファイルを開く」で `sample.dsp` を選びます。
3. Viewerの「ファイルを選択」で `sample.dsf` を選び、同じマークが表示されるか確認します。
4. ブラウザー版と追加したアプリで、操作しづらいボタンや表示の欠けがないか確認します。
5. ファイル管理アプリのアイコンも記録します。ただし、ホーム画面追加による文書アイコンの登録は保証していません。白い表示だけでファイルが壊れているとは判断しません。

## 開発側の検証記録

- `ecb3b60`のstaging配信: https://9e2fb509.dsf-studio.pages.dev 。固定URL・staging共通URLとも36資材のhash一致を確認。
- 配信されたStudio／Viewerを独立したChromeで操作し、DSP読込、DSF読込、未保存保護、インストール案内を確認。配信検証では受信イベントだけ模擬し、実ZIPを使用。
- Chrome 154.0.8037.93の隔離プロファイルでは、標準設定と `FileHandlingIcons` 指定を比較しても文書用ICOは生成されなかった。利用者のブラウザー設定は変更していない。
- DSFのコード／service workerから独立した最小PWAでも、ハンドラーは登録されるが文書PNGへのHTTP要求がなく、アプリ用ICOだけが生成された。PNGの配信失敗やDSFのキャッシュだけでは説明できない。ブラウザーまたは検証環境に依存する条件の切り分けが残る。
- 上記は隔離環境内の開発者APIによるインストール。通常のWindows画面からの新規インストールとExplorer表示を保証する結果ではない。Mac／Android実機は未確認。
