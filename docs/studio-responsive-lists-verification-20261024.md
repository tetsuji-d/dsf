## 表示崩れの原因と変更

1. リーズの表紙が旧一覧の `works-thumb` クラスを共有し、実Studioの `body[data-device="mobile"] #works-room` にある名前付きグリッド配置を継承していた。新一覧に意図しない列が生じ、題名が細い表紙列へ押し込まれていた。新一覧の表紙クラスを独立させ、表紙／情報の配置領域を明示した。
2. 表紙と欠損時の枠は9:16・角丸なし。狭い画面でも表紙と題名を隣接させ、URLとコピー操作、版・状態・日付、操作を読みやすい順に折り返す。
3. スマホ相当の幅は主要操作を44px以上、検索・URL・設定入力を16pxにした。左右16pxの余白を確保し、一覧の余白が二重になる指定を取り除いた。ダイアログの操作も折り返す。
4. モバイルヘッダーの横並び指定が760px以下に限定され、横向きではリーズへのボタンが大きく崩れていた。実際の `data-device="mobile"` 状態に適用し、リーズ画面で重複していた現在地名も整理した。
5. Homeでは旧カードの中央寄せとリードタイトルの改行禁止が残っていた。新一覧内で左揃え・長文折り返しにし、更新日への重なりを修正した。
6. fixtureにも実画面と同じ `#works-room` と幅に応じた `data-device` を設定した。画面幅だけでなく実際の祖先・状態に対するCSSを検証する。

## 読み込み待ちへの追加修正

実stagingのHome→リーズ移動で、読み込み表示が残る現象を再確認した。コードには認証ユーザーのオブジェクト同一性で画面の有効性を判定する経路があり、同じUIDでオブジェクトが置き換わると、結果もエラーも描画されなくなることを確認した。ライブで発生した瞬間の認証オブジェクトは取得していないため、実発生の引き金まで断定しない。

画面の世代番号・UID・ログアウト検知で有効性を判定するよう修正。同じアカウントのユーザーオブジェクト更新では画面を維持し、ログアウト・別アカウント・破棄した旧画面は引き続き無効化する。操作時は現在のユーザーからトークンを取得し、その前後で有効性を確認する。取得キャッシュ側のアカウント分離は変更していない。

`verify-edition-reads-session.js` で同UIDオブジェクト更新、古い画面・古い認証コールバック、ログアウト、同UID再ログイン、state/authのUID不一致、明示破棄を確認した。最終stagingではスマホ幅でHome→リーズ・更新、PC幅で2回連続のHome→リーズ往復が完了した。
