# Flow画像回り込み：実組版の技術検証

2026-09-10。設計の第2段階。Studio本体・保存・発行への接続は行わない。

## 実行

Vite起動後、`/scripts/fixtures/flow-image-wrap-lab.html` を開く。
実際のFlowDocumentの前段落・アンカー段落を編集し、既存のDOM計測で再ページ化する。
サンプル画像はローカルで生成した800×1000 WebP。アップロード・保存はしない。

ブラウザ検証：`node scripts/verify-flow-wrap-experiment-browser.cjs`
必要に応じて `DSF_PLAYWRIGHT_MODULE` と `DSF_BASE_URL` を指定する。

## 再利用と今回の追加

- `flow-pagination.js` の `createFlowPaginationIterator` とruntime checkpointを再利用。
- `flow-dom-measurer.js` の計測・生成ページ描画を同じ矩形領域へ適用する。
- `flow-document.js` と `grapheme.js` の段落ID・文字範囲・grapheme境界を維持。
- `js/fixtures/flow-wrap-composition.js` が画像の排除領域、矩形ごとの組版、アンカー移動を検証する。
- 結果はruntime-only。実エディターからのimport、既存Flowモデルの変更、新しいDSP仕様はない。

## 検証対象

横書き・縦書き、1つの段落に紐づく1オブジェクト。
画像周囲の矩形を本文の進行順に処理する。画像のある帯は広い方の片側だけを使用する。
中央画像の両側を同時に使用する行・列分割は未対応。帯の境界は既存行・列送りの外側へ丸める。
最低3字分の幅・高さがない片側の領域は使用しない。
画像の位置・サイズはページを移動しても不変。

まず全幅のページでアンカーの到達を検出し、同じcheckpointから回り込み領域を試す。
画像によりアンカー先頭が入らなくなった場合、アンカー直前までを画像なしで確定し、
画像とアンカーを次ページへ送る。確定した前ページには戻らない。
空のページでも画像とアンカーを置けない場合は停止する。画像の複製、本文の切捨て、無制限の再試行はしない。
手動改ページは矩形だけでなく物理ページを終了させる。

全出力fragmentのUTF-16・grapheme範囲と元の段落を照合する。
空段落も一度だけ存在することを確認する。ソースは変更しない。

## 結果

Chromeで47ケース合格。44,856個の描画範囲を確認（ルビ・圏点4,320文字を含む）。

- 全文の欠落・重複、grapheme分断なし。cold再計算のページ境界が一致。
- 画像とアンカー段落の先頭は同一ページ。画像は一度だけ出現。
- 追加文章に追従して画像が移動し、追加を戻すと元のページへ戻る。位置・サイズは不変。
- 画像による押し出しが生じる4ケースを確認。
- 日本語縦・横、英語横、中央・左右、四角・帯、空段落、改行、結合文字、絵文字、手動改ページを確認。
- 表示本文も元の段落と照合。文字がページ外・画像内に出ないことをDOM Rangeで確認。
- 不正画像寸法・余白、アンカー欠落、本文領域消失、ページ上限、未対応の扉配置を拒否。
- 計測DOMを成功・失敗ともに破棄。

これらは検証サンプルでの結果。任意の実作品や全端末の保証ではない。
