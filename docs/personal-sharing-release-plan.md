# 個別共有・閲覧のみの一般公開準備

更新: 2026-09-23。公開日未定。ステージング配信時に指定2アカウントのみ有効化。一般公開は無効。

## 完了した範囲

- 作品単位の閲覧招待・承諾・辞退・解除、最新保存済み原稿の読み取り。
- 共有相手には出版スペース所属や編集権限を付与しない。
- APIで本文・画像の再取得時に所有者、受信者、作品、保存世代、共有状態を検査。
- 招待の承諾期限は1/3/7/14/30日・無期限。承諾後は解除まで閲覧可能。
- 終了した招待を一覧から整理。有効な招待・共有は削除しない。
- 招待時の一覧上限は有効な共有を維持しながら古い終了履歴を整理する。元の招待記録は保持。
- 旧保存方式・管理対象画像・未対応画像の読み取り専用診断。診断は原稿・画像・公開状態を変更しない。

## 公開を止めている条件

| 項目 | 状態 | 合格条件 |
| --- | --- | --- |
| 非公開原稿の閲覧共有 | ローカル試験済み | 実アカウントでも招待から解除まで成功 |
| 旧Firestore原稿の準備 | 所有者用アダプター実装・自動試験済み | 所有者の明示操作、バックアップと再読み取り検証、競合拒否、失敗時に元原稿を維持 |
| 画像の非公開保存 | 準備ボタン接続・実UI試験済み | 下記の所有者経路が完成すること |
| 所有者の通常編集画面 | ローカル実エディター試験済み | 非公開画像の表示、編集、再保存、新規貼り付け、再読み込みを確認。公開保存へ戻さない |
| 期限・解除・アカウント切替 | 自動試験あり | 実アカウントでも別人の招待・別作品を取得できない |
| 対象アカウント制限の撤去 | 未実施 | 上記合格後に別の公開作業で実施 |

### 移行の実装上の注意

`server/private-authoring/maintenance.js` の全APIは公開しない。`personal-sharing-preparation.js` が所有者・マイスペース所属・アカウント状態・共同編集境界を毎トランザクション検査して、移行だけを限定公開する。ロールバックや任意パス指定は提供しない。

`server/shared-image-migration.js` は、出版スペースの共有編集へ登録するために画像参照を非公開参照へ書き換える。
所有者の通常ロードに非公開画像の認証付き取得と表示URLの復元を実装済み。保存時は元の非公開参照へ戻す。
「個別共有の準備をする」で旧原稿の移行と画像コピーを順に実行する。原稿バックアップまたはpreviousHeadを保持し、途中失敗時は招待を有効にしない。

共有解除や個別共有フラグの無効化によって、所有者まで自身の原稿・画像を読めなくしてはならない。
新しい画像の追加も公開R2へ出さずに完結させる。既存公開画像・既存Releaseは自動削除しない。

## 実アカウント試験の範囲

- 所有者: `@tetsuji`、閲覧者: `@tetsujiro`。
- 元の「潮騒の図書館」は編集せず、マイスペース内の試験用コピーを使う。
- ステージング限定で2アカウントを有効化。最初に本文のみ、次に画像を含む原稿で実施。
- 招待前に対象作品を確認 → 受信側で承諾 → 閲覧・編集不可 → 所有者の更新後に再表示 → 解除後の再取得拒否。
- 期限切れ、辞退、再招待、履歴整理、別アカウント切替、保存競合、移行失敗と再試行を確認。
- 画像について公開バケットへの新規書き込みがないこと、既存本文・Releaseが変化しないことを確認。
- 実アカウントではユーザーから招待・承諾・閲覧の成功報告あり。所有者の読み込み・保存不具合も報告されており、一般公開は未実施。ローカルfixtureの成功と区別する。

## 所有者の非公開画像経路（2026-09-23）

- `/api/projects/{projectId}/assets` のPOSTと `assets/{hash}` のGET。既存のauthoring許可範囲、本人確認、停止状態、保存世代を検査。個別共有フラグとは独立。
- 出版スペースの共有編集へ登録済みの場合は拒否し、既存の編集ロック経路を利用する。
- 通常エディターで読み込んだprivate R2原稿の新しい画像は非公開保存。既存の公開画像参照はこの変更では移行しない。
- 所有者のローカル復旧用に画像Blobを既存IDBへ保持。クラウド保存ではBlob URLを保存しない。
- Press配信ページ・公開サムネイルの明示アップロードは従来の公開経路。公開前の原稿画像はその経路に流さない。
- 新規作成時の初回保存、ローカルコピーを別プロジェクトとして開く経路、ダッシュボードの非公開サムネイル表示は別途検証・整備が必要。
- 検証: `node scripts/verify-owner-private-images.mjs`。実UIは `PERSONAL_SHARING_FIXTURE=true OWNER_PRIVATE_IMAGE_FIXTURE=true PORT=5251 node scripts/serve-shared-studio-fixture.js` と `OWNER_IMAGES_URL=http://127.0.0.1:5251 node scripts/verify-owner-private-images-browser.cjs`。

## ステージング招待試験手順

1. @tetsujiでステージングへログインし、マイスペースの試験用コピーを選ぶ。元作品や編集中の別タブは閉じる。
2. 作品カードのメニュー → 個別共有。必要な場合だけ「個別共有の準備をする」を実行する。
3. @tetsujiroを検索して相手を確認し、「閲覧のみで招待する」。
4. 別のChromeプロフィール等で@tetsujiroとしてログイン。ヘッダーのお知らせベルで招待を承諾し、左メニュー「共有された作品」から開く。
5. 本文・画像が表示され、編集できずプレビューは開けることを確認する。
6. 所有者が試験用コピーを更新・保存した後、受信側の表示が約10秒で最新保存内容へ更新されることを確認する。開いているViewerプレビューは開き直して確認する。
7. 所有者が共有を解除し、受信側の再取得が拒否されることを確認する。

自動テストは送信先をfixtureアカウントに限定。実アカウントへの招待送信・承諾はユーザーが実施する。
実装上の上限: 管理対象のWebP画像のみ、移行前検査は最大32画像・64MB。未対応・欠損画像がある場合は移行せず取り込み直しを案内する。

## 共有導線・保存セッションの修正（ステージング配信前）

- 招待通知はヘッダーのアカウントアイコン左のベルへ集約。個別共有と出版スペースへの招待を分けて表示する。
- 承諾済みの個別共有作品は左メニュー「共有された作品」から開く。選択中の出版スペースによらないアカウント単位の一覧。
- 閲覧のみでもViewerプレビューを利用できる。編集・保存・発行は許可しない。
- 閲覧中は10秒ごと（表示中のみ）とタブ復帰時に権限と最新保存原稿を確認する。未保存の文字入力は共有しない。プレビュー生成中や未保存の共同編集がある場合は原稿差し替えを保留する。既に開いたViewerは開いた時点のプレビュー。
- 所有者のロード失敗で前の保存セッションを破棄しない。同じ作品の二重ロードをまとめ、初回のローカル復元が明示的に開いたクラウド原稿を上書きしないようにする。
- 新たな原稿形式、アクセス権、公開先、許可アカウントは変更しない。
- 回帰試験: `PERSONAL_SHARING_FIXTURE=true OWNER_PRIVATE_IMAGE_FIXTURE=true PORT=5256 node scripts/serve-shared-studio-fixture.js`、`PERSONAL_SHARING_URL=http://127.0.0.1:5256 node scripts/verify-personal-sharing-live-browser.cjs`。試験ごとにfixtureを再起動する。

## 全ページ共通の通知モーダル（2026-09-24、未配信）

- Horizon、Studio、Viewer、マイページのヘッダーベルで、同じアカウントの個別共有・出版スペース招待を一覧表示。画面を移動せず詳細を読み、承諾・辞退できる。運営画面の認証ヘッダーにも接続。
- ベル横の数字は未読件数。未読0も表示。詳細を開いて既読にするだけでは参加・閲覧権限を付与しない。通信失敗時は `!` と再試行案内を表示する。
- 共有作品へのリンクは別タブで開くため、編集中の原稿を維持する。招待送信機能や共有権限は変更しない。
- 個別共有の `readAt` をサーバーに保存し、ページ移動・再ログイン後も既読を保持。承諾待ちと未読は別状態。
- 検証: `PERSONAL_SHARING_FIXTURE=true OWNER_PRIVATE_IMAGE_FIXTURE=true NOTIFICATIONS_FIXTURE=true PORT=5259 node scripts/serve-shared-studio-fixture.js` → `node scripts/verify-account-notifications-browser.cjs`。別の初期化済みfixtureで従来の共有・保存ブラウザ試験も行う。
