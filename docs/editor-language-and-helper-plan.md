## 目的と合意済みの方針

- 通常表示でもEN-GB等の選択言語を表示し、その言語の組版で直接編集できる。
- UIのJA/ENはプロフィールメニューに移す。本文言語のボタンは制作画面に残す。
- 呼び出したヘルパーを知りたい場所へドラッグすると説明する。対象をクリックしても同じ説明を開ける。
- アイコン主体の密度、既存の色・デザイン、キャンバスの広さを維持する。
- 説明はJA/ENの確定した内容から表示する。初期実装では生成AI、外部通信、会話ログを導入しない。

## 現状の確認

- `js/flow-runtime-pages.js`の通常resolverは、同一Flowの本文に欠落訳または古い翻訳があるとFlow全体を原文へfallbackする。
- `editor-compare`だけは保存済み翻訳と欠落訳の一時的な空欄を表示できる。通常/分割で見える内容が異なる。
- 比較scopeの空欄は原稿コピーだけに存在し、表示だけでは保存しない。通常表示への導入にもこの性質が必要。
- `js/flow-translation-compare.js`と`js/app.js`が表示モード、選択言語、直接編集を接続している。
- `studio.html`のデスクトップ/モバイルヘッダーにJA/ENがある。既存`setStudioUILang`とlocalStorage設定を再利用できる。
- プロフィールのHelpは文言のみで、操作ヘルプへの接続がない。リボンにはtitle/aria-labelを表示するtooltipがある。
- 既存比較ブラウザ検証で、原文編集後も英訳が保持されること、通常resolverの原文fallback、分割での未翻訳入力、Undoを確認済み。

## 実装順

追補: [多言語原文・手動翻訳・原稿取り込み](multilingual-authoring-use-cases.md)を前提とする。L1着手前に言語の役割を整理し、L1は英語原文→日本語訳も検証する。L2に新規原文言語の明示を加え、全文翻訳原稿の取り込みはL3として別の試作・実装単位に分ける。

### L1: 通常/分割の翻訳表示を統一

利用者の動作:

- 通常 + EN-GBは英語だけを横書きで表示する。原文を見たい場合はJAを選ぶ。
- 分割 + EN-GBは左を原文、右を英訳にする。分割から通常へ戻っても本文言語の選択を維持する。
- 分割中に原文側を選んだ場合はJAがアクティブになることを、本文言語とペイン枠で明示する。切替時に暗黙に英語を選び直さない。
- 保存済み英訳は原文更新後も表示し、対応段落を「要確認」とする。欠落訳は「未翻訳・クリックして入力」として表示する。
- 未翻訳と、意図して保存した空文字を区別する。表示・フォーカスだけでは本文や確認状態を書き換えない。
- 現在の短いステータス行に本文言語、書字方向、ページ進行方向を表示する。言語名だけから方向を決めず、既存の言語別設定を参照する。
- 未翻訳/要確認の件数と次の該当箇所への移動を用意する。該当なしや一時的な組版待ちは理由を表示する。

実装:

- Editor用の表示方針を共通化し、通常/比較で利用する。公開用の既定resolverへ比較の許可を広げない。
- sessionScope、projection署名、pagination cache、直接編集可否、空欄placeholder、検索結果への移動を一緒に見直す。
- `editorFlowScope()`、通常projection呼出元、比較projection、`allowMissingTranslation`の分割限定条件を点検する。
- 組版プロファイルがない場合は説明付きの設定導線を示す。黙って原文へ戻さない。
- 原文と翻訳でページ数が異なるため、通常/分割や言語変更後の位置は段落IDと既存source mappingから復元する。
- IME変換中・再組版中の切替を共通ガードに通す。選択言語だけ更新されて表示が古いまま残る状態を防ぐ。
- 発行、印刷、Viewerプレビューは引き続き既存の出力契約を使用する。編集用空欄や未確認訳の表示許可を流用しない。出力との相違がある場合は理由を案内する。

主対象: `js/flow-runtime-pages.js`, `js/flow-translation-compare.js`, `js/app.js`, `js/flow-editor-session.js`, `js/i18n-studio.js`。
完了条件: 未翻訳/古い翻訳を含むFlowでも通常の英語表示・入力・検索移動が可能。表示のみでは原稿に差分がなく、編集は一回のUndoで戻り、公開用resolverの回帰検証が通る。

### L2: UI言語をプロフィールメニューへ移動

- 常設ヘッダーからJA/ENを除き、プロフィールに「表示言語 / Language」「日本語 / English」を置く。
- 未ログイン時もアカウントメニューから到達できるようにする。言語変更にログインを要求しない。
- デスクトップ/モバイルとも同じ導線にする。現在の選択を明示する。
- 既存setStudioUILangと保存キーを再利用。本文言語、原文、翻訳、プロジェクト設定には影響させない。
- UI切替によるメニュー再生成後のフォーカスを復元する。再読み込み後も選択を保持する。

主対象: `studio.html`, `js/app.js`, `js/i18n-studio.js`, 対応する既存ヘッダー/アカウントCSS。
完了条件: ログイン前後、狭い幅、JA/EN往復、再読み込みで利用でき、本文言語が変わらない。

### H1: 操作説明の共通定義とヘルプ入口

- 安定した操作IDと`data-help-id`を入口にする。表示文言やDOM内の位置をIDにしない。
- 共通定義は名称、短い説明、適用対象、手順、既存ショートカット、関連項目、現在の利用可否と理由を持つ。
- 実際の操作可否判定を参照し、ヘルプ専用の別条件を作らない。全操作を一度に移行せず対象を段階的に増やす。
- 同じ定義からtooltip、ヘルパー吹き出し、検索可能なヘルプを提供する。
- 既存commandを呼ぶ層と説明データを分離する。WebMCPは将来このID/説明/利用条件を参照できる構成にするが、外部ツール登録は本単位に含めない。
- 右上に「?」を常設し、プロフィールのHelpも同じ入口へつなぐ。リボン折りたたみ時にも開ける。
- 開閉式のオーバーレイパネルに「場所を指して調べる」「目的で検索」「操作一覧」を配置する。閉じるとキャンバス幅は元のまま。
- 説明から「操作場所を示す」を選ぶと対象を強調する。編集や発行などの操作をヘルプ閲覧だけで実行しない。

追加モジュール案: `js/studio-help-registry.js`, `js/studio-help.js`, `css/studio-help.css`。既存tooltip/i18n/リボンとの接続を小さく保つ。
完了条件: 同じ機能の名称・無効理由がtooltipとヘルプで一致する。対象のない説明は関連手順へ案内し、DOM再描画で壊れない。

### H2: ヘルパー試作と実エディターへの接続

先に短い操作試作で大きさ、吹き出し、対象強調、ドラッグ/クリックを提示し、同じ操作契約で実装する。キャラクターは既存アイコンのテイストに合わせた小型SVGの仮デザインを使用する。

- 「?」から呼び出したときだけ登場する。自動で話しかけない。音や常時アニメーションは使わず、減速/動きの低減設定に配慮する。
- ヘルパーをドラッグ中に対象を強調し、離すと説明を固定表示する。吹き出しは名称、短い説明、現在の理由、「手順を見る」「操作場所を示す」、閉じるで構成する。
- 画面端、拡大縮小、分割キャンバス、スクロール後も対象に追随し、画面外へはみ出させない。
- ヘルプ対象選択中は専用overlayがポインターを受け取り、画像移動、トリミング、本文選択、ページ移動を実行させない。通常編集に戻す出口を常時表示する。
- ドラッグ以外に「場所を指して調べる」からクリック/タップで選べる。キーボードでは操作一覧から選択できる。対象選択をドラッグ専用にしない。
- 無効ボタンも周囲のラッパーから説明を得られる。pointer-eventsやdisabledのために理由が読めなくなる実装を避ける。
- Escape/閉じる/pointercancelで確実に終了し、入力フォーカスを復元する。モーダル/IME変換中は開始を待つ理由を示す。
- 装飾キャラクターは読み上げ対象から除き、説明・選択状態・閉じる操作をアクセシブルにする。色だけで対象を伝えない。
- 未登録の場所には「この場所の説明はまだありません」と関連カテゴリを表示する。推測の説明は生成しない。

完了条件: ドラッグ、クリック、タッチ相当、キーボード、Escで同じ説明に到達できる。対象選択前後で本文・画像配置・履歴・保存状態が変わらない。

### H3: 目的別ヘルプを拡充

初期公開分を以下に限定し、実装済みの操作だけを説明する。

1. 英語だけを表示する、原文と比較する、未翻訳に入力する、要確認を確認する、UI言語を変える。
2. キャンバスで編集する、原稿を開く、検索・置換する、Undo/Redoする。
3. 行内の文字揃えと行のまとまりの配置、適用範囲、扉ページの指定を区別する。
4. 画像の追加、選択、回り込み、キャプション、本文領域ガイド、コピー/貼り付けを説明する。
5. 保存、Viewerプレビュー、印刷、Horizon発行の違いと、現在の失敗理由への対処を説明する。

JA/EN双方を用意し、目的の同義語でも検索可能にする。例:「英語だけ」「横書き」「English」「single view」。詳細な内容も同じデータを使い、別画面表示が必要になった場合に二重管理を避ける。

## 検証方針

- L1は部分翻訳・全文翻訳・原文更新後・空文字・プロファイル欠落で確認する。通常/分割/原稿、JA/EN-GB/EN-US/KO、Fixed画像ページ選択、言語ごとのページ数差を含める。
- 言語切替後の英語横書きとスクロール方向を実測し、表示だけでstate.blocksが変わらないこと、直接入力・Undo・検索移動をChromeで確認する。
- 既存比較・検索・置換・直接編集・発行preflightのうち影響範囲に応じた検証を実行する。Editorの表示許可が出力の検査を弱めていないことを確認する。
- ヘルプは通常/分割、明暗テーマ、狭い画面、リボン折りたたみ、JA/EN、対象再描画、無効ボタンで確認する。
- ヘルプ対象選択では作者データとHistoryが変わらないことを検証する。クリック後のUI状態だけでなく、実際のドラッグ/中断操作も確認する。
- 実装単位ごとに必要な既存検証とstaging buildを行う。計画書だけの変更では製品テストやbuildを実行しない。

## 保存・公開・作業境界

- DSP/DSF、Firestore、翻訳本文、段落ID、確認状態の保存仕様は追加・変更しない。
- UI言語は既存端末設定を継続する。ヘルパー位置や会話ログをプロジェクトへ保存しない。初期はヘルパー表示状態をセッション内に限定する。
- ヘルプを開く/対象を指す行為から編集操作を発火させない。今後「実行」ボタンを追加する場合も明示操作と既存command/Undoを経由する。
- 実装着手はL1から。L1/L2が完了してからH1/H2/H3へ進む。WebMCP実接続はこの使い勝手の改善の後に再開する。
- コミットとstagingデプロイは各段階の確認後、ユーザーの依頼に応じて実施する。productionやRulesの変更は含めない。

## 2026-09-13 実装・確認結果

- 通常のEditor scopeも比較scopeと同様に保存済み訳/一時的な未翻訳空欄を表示する。原文更新後の訳を保持し、未翻訳/要確認の表示と次の該当ページへの移動を追加した。
- 分割から通常に戻る際はアクティブな本文言語を維持する。日本語を特別な原文として扱わない。原文言語/本文言語/実際の書字方向/ページ方向を短いステータスへ表示する。
- プロファイル欠落時は原文へ戻さず、理由と「選択言語の組版を準備」を表示。押した場合だけ全Flowの該当言語の欠落プロファイルを準備し、一回のUndoで戻せる。本文・確認状態は作成しない。
- UIのJA/ENはプロフィールに移動。デスクトップ/モバイル・未ログイン状態でも利用でき、端末設定を継続する。言語切替後にメニューとフォーカスを保持する。
- 新規作品で言語と方向を指定できる。Flow追加では作品言語から原文言語を指定し、作品の方向設定を表示する。Flow追加から作品全体のページ方向は変更しない。
- 空の新規原稿に日本語の仮本文を保存しない。既存の入力欄placeholderを使用する。
- 作品の既定言語は専用selectで明示する。言語列並べ替えでは既定言語を変更せず、既存Flowの原文言語も維持する。
- 保存済み言語キーは維持したまま、大文字小文字の違うEN-GB等も表示名の辞書を参照できるようにした。
- 英語原文→縦書き日本語の部分訳、欠落訳入力/Undo、組版準備/Undo、UI言語変更、既定言語、Flow追加/取消、新規作品、モバイルと設定再読込を新規Chrome検証で確認した。
- 既存の多言語authoring、直接編集、検索、置換、比較、画像リボン、末尾Flow追加の検証とstaging buildが通過。既存fixtureはモジュール読込後に一括初期化し、bootstrap中の一時的な不整合を回避した。
- 検証: `scripts/verify-editor-language-settings-browser.cjs`。既存 `verify-flow-multilingual-authoring.js`, `verify-flow-direct-edit.js`, `verify-flow-replace.js`, `verify-flow-search-browser.cjs`, `verify-flow-replace-browser.cjs`, `verify-flow-translation-compare-browser.cjs`, `verify-studio-ribbon-followups-browser.cjs`。
- 発行/Viewer/印刷の既定resolverは変更しない。全ての既存メニューの英訳、ヘルパー、全文取り込みは今回の完了範囲に含まない。コミット・デプロイは未実施。
