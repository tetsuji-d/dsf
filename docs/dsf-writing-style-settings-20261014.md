# Writingの線・文字設定と英語UI

2026-10-14。対象は `feature/dsf-writing-w0` のReader接続Writing。下記は実装・検証記録。iPhoneのファイル選択修正 `889a7d6` はステージング反映後にユーザーが実機でDSFを開けることを確認済み。その後、残る本書のWriting修正についてもコミットとステージング反映の指示を受けた。本番は対象外。

## 設定UIとデータ

- ペン／線／図形の設定は、ライブ見本を太さより上に表示。ページ・レイヤーサムネイルと同じ描画処理を使用する。
- 先端4種は画像付きボタンで選択し、始点・終点を個別指定。丸など塗られた先端の軸線は形状内部で止める。短い線で両先端が重なる場合、軸線を省く。
- 線・矢印・四角・楕円は実線／破線／点線／一点鎖線。`lineStyle` の省略時は実線。選択後の設定変更、履歴、書出し、再読込、共有用ファイルにも保持する。
- 文字入力の書式欄に、枠線の有無・色・太さと、塗りの有無・色を追加。初期状態は枠なし・透明。保存する任意フィールドは `boxStyle:{stroke:null|HEX,fill:null|HEX,width:number}`。widthは既存Writingと同じページ座標単位、UIではmm相当。元の本文とフォントには変更を加えない。
- プラットフォームのメニュー言語と連動して日英を切替。ツール、設定、色名、操作メニュー、履歴の表示名、読み上げラベルを翻訳する。原稿、入力文字、ファイル名、保存済み履歴データの操作名は書き換えない。

## 手書き変換の検討

現在の手書きは画像ではなく、座標列・筆圧・太さ・墨量等を保存してSVGで描画するベクター。直線・矢印・四角・楕円もベクターであり、文字ツールはUnicode文字列とフォント・配置情報を保存する。「画像からベクターにする」処理は既存筆跡には不要。

追加するなら、次の順を推奨する。今回は認識処理自体を実装していない。

1. **選択した筆跡を整える**：折れや余分な点を減らす。ページ座標に対する誤差上限を設け、元の筆跡と候補を比較して適用する。筆ペンのカスレや蛍光マーカーの断面は消さない。
2. **図形に変換**：直線・四角・楕円を候補表示し、ユーザーが選択して通常の図形オブジェクトに置換する。点線・先端・色等を再編集できる。描き終わりを勝手に図形へ変えない。
3. **手書きを文字に変換**：認識候補の修正画面を経て通常のテキストボックスへ置換する。日本語／英語、縦書き、複数筆跡の読み順を検証する必要がある。認識エンジンは未選定。オフラインの日本語精度・モデル容量・ライセンスを調査してから選定し、外部送信を前提としない。

変換は原本へ作用せずWritingだけに適用する。元筆跡を残した「変換結果を複製」が初期値、置換を選んだ場合も本全体30操作の履歴に1操作として記録する。履歴を超えた後も原筆跡を残したい場合は複製を選ぶ。ロックされたオブジェクトは変換しない。変換後のテキストも既存の字形検証・サブセット保存を通す。

## 検証

`node scripts/writing-w1/verify-style-settings.mjs`：丸先端の軸線48条件、短い／長さゼロの矢印、4線種、英語／日本語表示、枠・塗りのUndo/Redo、不正データの原子的拒否、編集用・共有用DSF再保存、原本entryのbytes不変。

既存の文字配置、道具、履歴30操作と先読み、ロック、Reader見開き接続、8種類の画面サイズ別配置、モバイルの拡大防止の回帰検証に合格。ステージング用buildと配布allowlist・オフライン資源の検証にも合格。

ブラウザー実操作（1280×720と390×845）：日英切替、画像付き先端、ライブ見本、両端丸の一点鎖線、点線の楕円、文字の枠と塗り、選択後の線種変更、Undo/Redoを確認した。英語UIで入力した「設定」は本文・レイヤー一覧で日本語のまま保持。編集用DSF作成後にReaderへ戻り、再びWritingで開いて形状・線種・文字・枠・塗りの保持を確認。ブラウザーconsole errorなし。検証時の言語とviewportは元に戻した。

## 分割画面での設定パネル修正

下部のレイヤーボタンを設定パネルの基準として引き継ぎ、横置き時の最大高さを240pxにしていたため、673×833の表示領域ではヘッダーとフッターを除く設定領域が約80pxになっていた。設定を開く際に現在の道具の設定ボタンを基準に戻し、設定パネルは画面内で560〜680pxの高さを優先する配置に変更。低い画面では上下8pxを残す。PC幅の設定パネルは420pxにした。

実操作でレイヤー一覧→線を選択→設定を開く→画面幅変更を検証。分割画面相当674×834では設定領域約493px、390×845では約434px、845×390では約212pxを確保し、キャンセル操作も確認。配置テストでは下部の起点、画面上端・左端のオフセット、短い表示領域を含む18条件を追加。修正画面は `outputs/writing-w1/panel-layout-20261014/split-pane.png`。ローカルのみ、未コミット・未デプロイ。

## 設定内容の縦方向の圧縮

見本を110pxから52pxへ変更（筆ペンは72px）。見本の座標範囲も調整し、太い筆跡や矢印先端を切らない。先端4種と線種4種をそれぞれ一列にし、選択ボタンは高さ48px、色は44pxのタッチ領域を維持。12色は6列×2行、見出し・項目間・適用欄の余白も縮小した。

ブラウザー実操作で1280×720の日本語と390×845の英語を確認。選択した線の見本・先端・線種・12色がスクロールなし（設定領域clientHeight/scrollHeightとも484px）で表示された。丸先端・破線の変更と適用、筆ペンの墨量変更による見本の更新も確認。画像は `outputs/writing-w1/compact-settings-20261014/desktop-ja.png` と `mobile-en.png`。実機のタッチ操作は別途確認する。

認識機能は[オフライン認識と本全体の検索の検討](dsf-writing-offline-recognition-plan.md)へ分離した。今回は調査・設計のみで、エンジン導入やDSFへの認識情報追加は行っていない。
