## 今回の修正

1. 一般読者によるレビュー閲覧は、作品インデックスが存在し、public/unlisted、掲載・公開期間内、失効未指定の場合だけ許可する。投稿者自身とstaffの既存の閲覧・レビュー削除権限は維持。
2. 新規投稿のworkId、authorUid、projectId、releaseIdを現在の公開インデックスと照合する。公開版が更新された場合、古い画面からの投稿は再読込を案内。旧版に付いたレビューは作品単位で維持する。
3. 本人の評価票とgood/bad集計を同じトランザクション内で照合する。評価追加、切替、取消の正確な差分だけ許可。票だけ／集計だけ／別ユーザー票／無関係フィールドの変更を拒否。staffによる票単体削除も集計を壊すため拒否する。staffのレビュー非表示・削除は維持する。
4. クライアントはサーバーから公開状態とレビューを読む。投稿・評価直前にも公開状態を確認。集計はincrementを用い、同時評価の競合時も整合性を保つ。
5. 読込失敗時に前の一覧を残さない。投稿直後の対象1件はサーバーで再確認してから補う。旧一覧の無条件な合成を廃止。
6. アカウントや作品が変わった後の遅延応答を破棄。連続投稿・同時評価操作を抑止。下書きを再描画・失敗時に保持し、アカウント変更時は消去。エラーを表示して再読込を提供する。

レビューは従来どおり最大20件の取得範囲内で時刻降順に表示し、投稿直後の確認済み1件を必要に応じて追加する。全体の最新20件を保証するページングや複合インデックス追加は今回の範囲に含めない。

## 保留事項

- `badCount` は画面上非表示だが公開レビュー文書の一部。アクセス制御上の秘密ではない。実際に非公開化するには保存先の分離・移行の合意が必要。
- 既存の誤った集計値は自動修復しない。評価を取り消すと負数になる不整合などは更新を止める。必要なら別途、票の再集計を読み取り監査から検討する。
- 公開撤回後の新たなサーバー読込を制限するもので、既に閲覧・保存された文章の回収を保証するものではない。
- 改修を実環境で有効にするには、その環境へのルール／フロント反映が必要。フロントだけでは直接DBアクセスの問題は解消しない。
