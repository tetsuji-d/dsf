# DSF Writing 新仕様案

作成日: 2026-10-11。状態: 設計案。W0の隔離試作とW1ファイルAPIを実装。Readerとの往復は開発・staging build用フラグの下でローカル実装・検証済み。Horizon／Pressと本番は未接続。

[W0実装記録](dsf-writing-w0-report.md) に、JSON契約、派生フォント、PCでのオフライン検証結果を記載した。以下の製品仕様全体が実装済みという意味ではない。実ZIP処理はW1で追加し、製品Readerとの接続は今後行う。

[W1ファイル処理記録](dsf-writing-w1-report.md) に実ZIP・全entry検証・原本bytes保持・再保存のAPIを記載した。W1では原本の `resources.json` と `writing/resources.json` にfont descriptorを分離する。ZIP32 STOREを実装し、圧縮ZIP全般を受け入れるloaderにはしていない。製品Readerとの接続は残る。

DSFの発行内容を変更せず、その上に読者個人のWritingを重ねる。Horizonでダウンロード版を提供するリードは配信画面でも書き込め、その結果を履歴付きの編集用DSF、または履歴を含まない編集ロック済みの共有用DSFとして持ち出せる。

この文書では、会話で決まった製品方針と、それを実現するデータ契約案を区別する。現行のファイル仕様・製品コードの動作・配信環境はまだ変更していない。実装順と完了条件は[実装計画](dsf-writing-implementation-plan.md)を参照。

## 1 合意済みの製品方針

- 拡張子は `.dsf` を維持し、Writingを含む新仕様に統一する。過去のDSFを読み続ける互換処理や自動移行は今回の要件にしない。
- Horizon配信版とDSFファイル版は別の成果物。同じ発行内容を表すが、配信方法とデータの梱包方法が違う。
- Pressに「読者にDSFダウンロード版を提供する」を設け、Horizon発行と同時に提供できるようにする。現状のHorizonには、この読者向けダウンロード導線はない。
- ダウンロード版を提供しているHorizon配信版でもWritingを利用できる。
- ペン、筆ペン、サインペン、蛍光マーカー、テキストボックス、線、図形を用意する。書き込みの削除と履歴からの復元ができる。
- 元の本文・画像・レイアウトは不可侵。Writing操作は原本の内容、ページ順、リンク先、組版を変更しない。
- PressのDSF書き出しは原則として使用字形のサブセットフォントを同梱する。Writingのファイル保存時も、保存対象の書き込みに必要な字形へサブセット化する。
- 複数書体の併用を前提とし、エディターではプロジェクトの書体管理と、リボンで選択中のテキストへ書体を適用する操作を分ける。
- 標準セットと追加カタログは、Writingでの新規入力・オフライン利用・サブセット保存・再配布まで利用できるオープンライセンスのフォントを中心に構成する。無料であることや商用利用可という表示だけで採用を決めない。
- 共有時は履歴を除いた編集ロック済みコピーを作れる。これは対応Readerでの編集制限であり、ファイル解析による改変を防ぐ保証ではない。

以下の具体的なフィールド、バージョン番号、履歴構造、提供停止時の扱いは実装のための設計提案である。

## 2 用語と保存種別

| 用語 | 意味 |
|---|---|
| リード | 作品・出版物そのもの |
| Horizon配信版 | サーバーのページデータと共有フォントを使って閲覧する成果物 |
| DSFファイル版 | 本文・画像・フォントを収録し、対応Readerで持ち運んで読めるZIPファイル |
| 原本領域 | Pressで確定した発行内容。Readerで再編集しない |
| Writing領域 | 原本の上に重ねる読者の書き込み |
| 書き込み / Writing | 日本語UI / 英語UIでの機能名 |

| 保存種別 | 内部値案 | Writing | 履歴 | Readerでの扱い |
|---|---|---|---|---|
| 通常版 | `original` | なし | なし | 新しい書き込みを開始できる |
| 編集用コピー | `writing-editable` | 現在の状態 | 保存済み全履歴 | 再編集・削除・復元できる |
| 共有用コピー | `writing-shared` | 確定した状態 | 収録禁止 | 表示・非表示のみ。編集や追記は禁止 |

共有用コピーの作成で、手元の編集用データを上書きしない。共有用をReaderで開いても「ロック解除」や「編集用へ変換」は提供しない。受取人が別レイヤーを追記する機能は後続検討とする。

Writingの非表示は原本を確認するために許可する。書き込みが非表示でも、書き込み付きファイルであることと共有用の状態はUIに残す。Writingを根拠に原本の作者名を変更しない。

## 3 利用可能になる条件

| 読み込み元 | Writing開始条件 |
|---|---|
| Horizon配信版 | 読者から閲覧可能で、同じReleaseのダウンロード版が `ready`、原本を完全取得・検証・端末保存できたこと |
| 端末の新仕様通常版DSF | ZIP・原本・リソース検証が完了したこと |
| 端末の新仕様編集用DSF | 上記に加えWritingと履歴の検証が完了したこと |
| 端末の共有用DSF | Writingの表示のみ |
| Studioプレビュー | 読書・リンク確認のみ。Writingは提供しない |

HorizonのWriting初回開始時は「書き込みの準備」として通常版DSFを取得する。検証済み原本を端末に確保してから開始し、配信停止や通信切断で書き込みを持ち出せなくなる事態を避ける。失敗時は読書を継続できるが、Writing開始は保留する。明示したダウンロード操作もない通常読書では、全DSFを先読みしない。

初期版はWritingをサーバーへ送らない。ログイン不要のローカルデータとし、Horizonの公開情報、作者のProject、Firestore、共有レビュー欄とは接続しない。ブラウザーのプロファイルを共有する場合は同じ端末データが見えることを、保存先の説明に記載する。

### オフライン利用

Writingはオフラインで描画・文字入力・削除・履歴復元・端末保存・編集用／共有用DSFの書き出しまで使える設計とする。2026-10-11のローカルUI試作では、準備後の通信遮断・reload・下書き復元・新規文字入力・編集用／共有用書出しをChromeで確認した。製品Reader全体への統合、ブラウザープロセス終了からの再起動、実機受入は残る。DSFファイルを持っているだけでReader自体を起動できるとは限らない。

初回はオンラインでReader本体、Writingのコード、ZIP処理、サブセット生成器、UI資源、選択したWriting用の完全版フォントを端末へ準備する。原本の全ページ・画像・サブセットフォントはDSFファイル、または検証済みの端末cacheから供給する。入力用の完全版フォントはアプリ側で書体・版・hashごとに共用し、各DSFには丸ごと収録しない。原本やWritingのサブセットに未収録の文字を入力する場合にも必要なため、DSFを開けたことだけで入力準備完了としない。

準備のない別端末でも、DSFだけで保存済み本文・書き込みの表示と編集用履歴の復元はできる。新しい字形を必要とする文字入力には、該当書体の完全版の事前準備が必要。未準備時も手書き・図形・既存オブジェクトの移動等は利用でき、再保存は収録済みの必要字形を欠落させずに処理する。保存済み内容の閲覧のために完全版フォントを再ダウンロードさせない。

「オフライン準備済み」は必要資源の取得・検証・保存完了後にだけ表示する。未準備のフォントや対応外の文字を必要とする場合は、その制限を表示し、黙って別フォントに置き換えない。アプリのインストール済み表示とは別に準備状態を管理する。

Horizonで新しい作品を探す、まだ取得していない原本をダウンロードする、Pressから発行する操作には通信が必要。取得済み原本を使うローカルWritingはオンライン認証や公開状態の再取得を起動条件にしない。ネットワークなしでブラウザーを終了・再起動しても使えることを受入条件とする。端末から消去されたアプリ資源・原本・フォントは再準備が必要となる。

## 4 Readerの操作

通常の読書モードとWritingモードを分ける。Writing開始時は通常表示にし、ページの曲面表示・覗き見・ページ移動アニメーションの途中では描画入力を受け付けない。見開きでは左右を独立した論理ページとして扱う。

| 道具 | 初期仕様 |
|---|---|
| ボールペン | 細い自由線。黒・赤・青を含む12色。0.3／0.5／0.7 mm相当の3段階（360×640の基準座標に換算。画面・印刷の実寸保証ではない） |
| 筆ペン | 筆圧による太細、入り・抜き、滑らかな筆跡。色・基準太さ。筆圧のないマウス・指では速度と端点処理から強弱を補う |
| サインペン | 不透明な太い自由線。色・太さ |
| 蛍光マーカー | 半透明の自由線。ビビッドからくすみ色まで35色の専用パレット。色・太さ・不透明度（現UI試作は0.48固定） |
| 修正液 | 不透明の白をWriting上に重ねる。原本を消去しない。独立した筆跡として選択削除・履歴復元できる |
| テキストボックス | プレーンテキスト、改行、色、文字サイズ、左右・中央揃え、横書き・縦書き |
| 線・矢印 | 始終点をドラッグして再編集、色、太さ、両端の矢印の有無。近傍の線・矢印の端点と図形のハンドルへスナップ |
| 図形 | 四角・楕円。8個のハンドルによるサイズ変更。Ctrlを押した描画・サイズ変更は正方形・正円。枠線、塗り、透明度（現UI試作は枠線のみ） |
| 選択 | 移動・サイズ変更・前後移動・削除。テキスト再編集 |
| 消しゴム | 触れたWritingオブジェクト単位の削除。線の一部だけを切る方式は後続 |

2026-10-11の道具UI更新: 「読む」は道具ではなく「閲覧／書き込み」のモード切替にする。閲覧は書き込みを表示したまま入力を止める。ペン類はキャンバス上部の下向きのペン先で選択し、選択したペンが下がる。ペン／線用12色と蛍光用35色を分け、道具ごとに色・太さを保持する（試作は画面を開いている間）。筆ペンは速度・方向・始端／終端からの距離を使って起筆・送筆・収筆を疑似表現する。

蛍光パレットは[ゼブラ公式のマイルドライナー35色紹介](https://www.zebraservice.jp/shop/c/c110502/)を参考に、画面用の独自色で構成する。製品インクの測色値や色再現保証ではない。スナップは座標の一致であり、図形移動後も追従する接続関係は持たない。初期ポイント編集は端点とサイズ変更ハンドルを対象とし、自由頂点・ベジェ曲線・回転は別途検討する。

Writingモードの1本指・マウス・ペン入力は選んだ道具へ渡す。ページ端タップやページリンクのホバー・タップを発火させない。ページ移動は専用ボタンで行い、2本指操作は拡大・移動へ渡す。描画中に2本目の指が触れたら未確定のストロークを取り消し、誤った線を残さない。ペン入力中はタッチ描画を抑制するが、機器固有のパームリジェクションを保証しない。

ページリンクは読書モードに戻ると利用できる。Writingを隠す操作と削除する操作を分ける。全消去は対象ページ／全ページを明示し、1件の履歴として取り消せるようにする。

ページ番号とWriting一覧から対象ページへ移動できる。スマホでは道具を下部バーにまとめ、詳細設定や文字入力が画面外に出ないようにする。キーボードで道具選択・Undo・Redo・選択削除ができるようにし、アイコンには日英の読み上げ名を付ける。

### 書体管理とリボンのフォント選択

| 場所 | 役割 |
|---|---|
| Studioのプロジェクト設定 | プロジェクトで使う書体一覧と既定書体を管理する |
| Editorのリボン | 選択中のテキストに書体・太さ・サイズを適用する。プロジェクト設定を毎回開かずに切り替えられる |
| Writingの文字ツール | 自分の書き込みに書体・太さ・サイズを適用する。作者のプロジェクト設定には書き戻さない |

フォント選択UIと認定書体のカタログは共通化する。Editorはプロジェクトで選んだ書体を優先表示し、「書体を管理」から管理画面へ移れる。Writingは利用可能な認定書体と端末への準備状態を表示する。作者が使った書体だけにWritingの選択肢を制限しない。本文の未知の書体を表示する際は実際の名前と未準備状態を示し、黙ってゴシック等へ読み替えない。

### 標準セット・追加カタログの採用方針

2026-10-11合意。標準セットは初期選択する書体、追加カタログは利用者が選んで追加する書体の一覧とする。両者に同じライセンス確認・描画検証を適用し、追加カタログを有料書体や作者専用書体の意味では使わない。書体一覧の追加と、入力用完全版のダウンロード・端末準備は別の状態として管理する。

SIL Open Font License（OFL）等のオープンライセンスを優先する。既存のNoto Sans JP／Noto Serif JPを初期候補とし、書体・版ごとに次の用途を満たすことを確認してからWriting対応として認定する。オープンライセンスという名称だけで一律に許可済みとは扱わない。

- Studio／ReaderへのWeb配信、必要な処理環境での利用、端末cacheとオフライン入力。
- 作者・読者による新規文字入力と、商用作品を含む成果物の作成・共有。
- Press／Writingでのサブセット化、必要な形式変換、DSFへの同梱と受取人への再配布。
- 受取人による保存済み内容の表示・履歴復元、および利用可能な完全版を準備した上での新規入力。

カタログには元書体のID・版・hashに加え、配布元URL、著作者／権利者、ライセンス名・版・本文・出典、確認日、予約フォント名や改変時の名称条件、用途別の確認結果を記録する設計とする。判定fieldと証拠の保存形式はW0で確定する。フォント内の埋め込みフラグや利用者の自己申告だけを利用許諾の根拠にせず、技術的な描画認定とライセンス確認を分ける。

「Writingで入力に使えるか」と「端末に準備できているか」を別々に表示・判定する。表示用サブセットの存在だけで新規入力用の候補へ追加しない。原本の書体が利用できない場合も、利用者が明示的に別の認定書体を選んでWritingを作れる。原本の書体や保存済みWritingは置換しない。

有料・独自ライセンスの書体を将来追加する場合は、同じ用途の許諾を個別に確認する。一般のデスクトップ契約やPDF埋め込み許可をDSF同梱・Web配信・Writing入力の許可と読み替えない。ユーザーによる任意フォントのアップロード・登録は引き続き初期実装の対象外で、今回の方針で実装範囲へ追加しない。

DSFには使用フォントに必要な著作権表示・ライセンス本文・改変時の情報を同梱し、通常版・編集用・共有用すべてで保持する。原本分は原本領域へ確定して保持し、Writing分は収録フォントとの対応を保つ。共有用から履歴を除去するときも必要なライセンス情報は削除しない。具体的なentry pathはW0で定義し、manifestとvalidatorの許可entryへ含める。

サブセット化は容量削減であり、利用許諾を不要にするものではない。OFLでも配布形態と改変内容に応じた条件を確認し、必要な名称変更を行う。Writing共有用の編集ロックは書き込み操作の制限であり、同梱されたオープンフォントのライセンス上の権利を取り消すものではない。

参照: [OFL公式FAQ](https://openfontlicense.org/ofl-faq/)（ソフト同梱、文書埋め込み、ZIP内配布、改変・予約名）、[Adobe FontsのライセンスFAQ](https://helpx.adobe.com/fonts/web/font-licensing/font-licensing.html)（用途別許諾の比較資料）。採用時は各フォントの実際の配布物に付属するライセンスを確認する。

### 選択範囲への適用

適用範囲の設計案は以下。文字単位の書体指定は範囲styleのデータ契約とEditor／Press／Reader間の検証を要し、UI部品だけの追加で対応済みとしない。

| 選択状態 | フォント変更の対象 |
|---|---|
| 文字範囲を選択中 | その範囲だけ。リボンへfocusが移っても選択範囲を保持する |
| 文字編集中でcaretのみ | 以後入力する文字のstyle。既存文字や原本全体を変更しない |
| テキストボックス／段落全体を選択中 | 選択したテキスト単位全体 |
| 複数の対象を選択中 | 選択した編集可能なテキストに適用。現在の書体が異なれば「混在」と表示 |
| 対象なし | 選択中テキストへの適用は無効。新規テキストの既定書体は別の明示操作で管理 |

書体変更は1回のUndo対象とする。読み込みと対応文字の確認が完了してから確定し、失敗時は元のstyle・文字・選択状態を保つ。共有用Writing、画像、手描き線では文字用フォント操作を適用しない。

文字列はプレーンテキストとして保持し、文字範囲ごとのfont/styleを別のrun情報で表す。結合文字やIME変換途中を壊さず、原稿側の文字範囲契約とWriting側の履歴に整合させる。サブセットの収集は各runに実際に指定された書体ごとに行い、書体一覧へ登録しただけの未使用fontをDSFへ同梱しない。

## 5 原本の識別と保護

Writingは `workId`、`releaseId`、`baseContentHash` に結び付く。対象ページは `language` と `pageId` で指定し、ページ番号は一覧表示のために毎回解決する。同じページIDでもReleaseまたは原本ハッシュが異なれば適用しない。

提案する `base.json` に、原本領域の全ファイルの相対path・MIME・byteLength・SHA-256をpath順で格納する。原本のメタデータ、ページデータ、ページリンク、画像、フォントを含め、Writing、外側manifest、format記述、mimetype、`base.json`自身は含めない。ファイル一覧は厳密に一致させる。

`baseContentHash` は既存のcanonical JSONシリアライザーで生成した `base.json` のUTF-8 bytesのSHA-256とする。これはファイル名やZIP全体のハッシュとは異なり、Writingの追加・編集・削除で変わらない。通常版・編集用・共有用の間で、原本領域の各ファイルの展開後bytesを完全に維持する。ZIP圧縮結果や外側manifestは変化してよい。

Horizonとportableではfont参照先とfont bytesが異なり得るため、両者の `content.json` やfontのハッシュを同一と扱わない。Pressが同じ確定組版から両方を作り、言語別ページID・順序・座標・テキスト・リンク・画像hashを照合する。フォントは同じ認定元書体・版から派生したことと、使用字形・メトリクス・組版結果の等価性を別に検証する。Horizonの公開Release情報に、そのportable版の `baseContentHash` を結び付ける。Horizonの共有CDNフォント自体のサブセット化は今回の変更範囲に含めない。

原本はPressでサブセット化と表示検証を完了した時点で確定する。その後のWriting保存では原本フォントを再サブセット化・拡張・置換しない。追加で必要な字形はWriting領域に収録する。

新しいReleaseにはWritingを自動移植しない。旧版の書き込みは一覧に残し、確保済みの原本で開く。翻訳ページにも自動転用しない。

原本不可侵はアプリのAPI境界と検証で守る。Writingコマンドには原本のsetterを渡さず、書き出し前後に全原本ファイルをhash比較する。ハッシュは破損・不一致の検出用であり、作者本人の真正性を証明する署名ではない。

## 6 ファイル構造とバージョン案

新しいDSF全体の形式を `formatVersion:3` とする。通常版もWriting付きも同じ形式を使う。拡張子 `.dsf` とMIME `application/vnd.dsf.content+zip` は維持する。

内部の固定ページ表現は現行delivery schema 2、言語manifest schema 1を再利用する。これは旧ファイル互換のためではなく、変更しないページ表現の番号を不用意に上げないためである。DSPのProject v7とReaderのWritingは別のデータモデルであり、WritingのためにProject全体を新しい番号へ変換しない。

```text
read.dsf
  mimetype
  format.json                DSF形式3と保存種別
  manifest.json              全収録ファイル一覧とhash
  base.json                  原本領域の固定ファイル一覧
  meta.json                  原本の書誌情報
  content.json               原本の言語index
  content/<language>.json    原本の固定ページ列とページリンク
  assets/images/...          原本画像
  fonts/...                  Pressで確定した原本のサブセットフォント
  writing/document.json      Writingの現在の状態とリソース参照
  writing/history.json       編集用だけに存在する履歴
  writing/fonts/...          保存対象Writingのサブセットフォント
```

通常版には `writing/` を置かない。共有用には `writing/history.json` を置かない。未知の追加ファイルを丸ごと保持する書き出しは行わず、定義済みの領域と参照資源だけを収録する。

`format.json` の編集用コピーの形は以下。hashとIDの値は説明用である。

```json
{
  "formatVersion": 3,
  "kind": "dsf",
  "copyKind": "writing-editable",
  "base": { "path": "base.json", "sha256": "<64桁のhash>" },
  "writing": {
    "schemaVersion": 1,
    "document": "writing/document.json",
    "history": "writing/history.json"
  }
}
```

通常版は `writing:null`。共有用は `copyKind:writing-shared`、`history:null` とする。保存種別を編集可否の正本とし、別の `locked` booleanを重複させない。

外側のarchive manifestはschema 2／`dsf-archive-manifest-2`へ更新し、形式3を必須とする。manifest自身を除く全entryをhash対象に含め、余剰・欠落・二重登録を拒否する。manifest自身は自己hashを持たず、配信時は外側のダウンロードdescriptorでZIP全体のhashを検証する。

旧DSFを新仕様として推測読込しない。未対応形式なら再出力を案内して停止する。過去DSFの変換ツールは作らず、必要な検証作品をDSP／元プロジェクトから再発行する。既存の元原稿・検証素材は削除しない。

## 7 Writingのデータ契約案

`writing/document.json` は `schemaVersion:1`、`documentId`、原本識別、`headRevisionId`、`pages`、`resources` を持つ。各ページは `language`、`pageId`、`objects` を持ち、配列の順序を重なり順とする。同じ原本に複数の編集用コピーを作れるよう、`documentId` を作業単位の識別に使う。

全オブジェクトは不変の `id` と `type` を持つ。座標は画面pixelsではなく原本の論理ページ座標を使う。現行は360×640。拡大、スクロール、見開き配置の逆変換で入力を論理座標に戻す。ページを跨ぐ1オブジェクトは作らず、ページ外をclipする。ページ寸法・向きの定義と原本が一致しないものは拒否する。

見開きをまたぐペン類の入力は、関係する各ページに別IDの筆跡オブジェクトを作り、1つの履歴revisionで確定する。左右の境界で筆圧・幅・筆ペン輪郭を再計算せず、同じ軌跡をそれぞれのページ座標に変換して枠外をclipする。このため各レコードには契約の許容範囲内で枠外の軌跡も保持する。単ページ表示・保存後もそれぞれのページに属し、別の見開きへ移った際に接続先を変更しない。Undo／Redoは1筆分まとめて扱い、選択や削除は各ページのオブジェクト単位。線・図形・文字の配置は開始ページ内で完結する。

| type | 内容 |
|---|---|
| `stroke` | `tool:pen/brush/marker/highlighter/correction`、pointsのx/y/pressure、確定した各点の幅、色、基準幅、不透明度、描画方式のversion。correctionは白 `#ffffff`・opacity 1に限定 |
| `text` | プレーン本文、rect、文字方向、揃え、style、font参照、確定した行／文字位置 |
| `line` | 始終点、線style、矢印設定 |
| `shape` | `shape:rect/ellipse`、rect、枠線style、塗りstyle |

自由線は保存したpointsから同じ線形状を復元できるようにする。1本の蛍光線内の重なりで色が不必要に濃くならないよう、ストローク単位の一時面で合成する。別ストローク同士の重なりは濃くなる。消しゴムは原本面に合成しない。

Writingの太さUIは全ペン類・線・図形をmm表示に統一する。内部の論理ページ座標は維持し、ボールペンと共通の96/25.4換算を使う。画面の物理的な実寸を保証する単位ではなく、拡大率とともに表示上の筆跡も拡大する。蛍光マーカーは縦幅を指定幅、横幅をその28%とする固定方向の長方形ペン先を軌跡に沿って移動した領域として描画する。点だけの入力も長方形とし、方向を変えても丸い端を付けない。

選択モードでは書き込みを長押し（PCは右クリックも可）すると、切り取り・コピー・貼り付け・複製・削除のアイコンを表示する。コピーは現在のWritingセッション内だけに保持し、同じDSFの別ページにも貼り付けられる。新しいDSFを開く／Writingを終了すると破棄し、OSのクリップボードやファイルには含めない。複製・貼り付けは新IDを割り当て、切り取り・貼り付け・複製・削除はそれぞれUndo可能な履歴に記録する。貼り付けのみ空白の長押しからも利用できる。画面幅820px以上では道具とペンを同時に表示し、それ未満では1ボタンの巡回切り替えを使う。道具は操作終了から約3.5秒で上端へ収納し、上端のタップ／マウスオーバーで再表示する。Undo／Redoとページ全体表示は収納せず、直接操作できる状態を保つ。

筆ペンの筆圧補正・速度補間・入り抜きは入力確定時に計算し、描画に使う各点の幅と再現に必要な形状情報を保存する。再読込時の端末性能やイベント時刻から太さを再計算しない。筆ペンの geometryVersion 2 は inkAmount（0〜1、必須）を保存し、墨量が少ないと12本の筆筋と隙間、多いと淡い輪郭の重なりでカスレ・滲みを疑似表現する。0でも乾いた筆跡を残す。物理シミュレーションではない。保存点列から決定的に描画し、object ID・ページ位置・乱数には依存しないため、コピー・見開き分割・再読込で模様を維持する。保存幅の外には拡張せず、描画時のみ最大約1,501点に間引く。geometryVersion 1 の筆跡は従来どおり描画する。

テキストは編集データと確定描画位置をともに保持する。再読込で自動再組版せず、編集確定時だけWriting側で組版する。対応文字を描画できる認定フォントを使い、ファイル版では必要なサブセットbytesを原本のfont参照または `writing/fonts/` に確保する。外部URLや端末の代替フォントに依存して書き出さない。初期版の自由なフォント持込・HTML・スクリプト・画像貼付は対象外。

### フォントのサブセット方針

| 保存対象 | 字形の収集範囲 |
|---|---|
| Pressの通常版DSF | ファイル内の全言語・全固定テキストページで必要な文字と字形。ルビ、圏点、リンクのページ番号など確定済みの表示も含む |
| Writing編集用DSF | 現在状態に加え、保存する全履歴・別の枝・削除済み文章の復元に必要な字形の和集合 |
| Writing共有用DSF | 確定した現在状態だけ。履歴でしか使っていない字形はWritingフォントからも除く |

文字のUnicode集合だけでなく、縦書きの句読点、合字、異体字指定、結合文字など、描画に必要な代替字形とOpenType機能を含める。画像に焼き込まれている文字のためだけにフォントを収録しない。筆ペン等の手描き線もフォントを必要としない。

元書体ごとに対象全ページの必要字形を集約し、ページ別に同じフォントを大量生成しない。太さの可変データは初期実装で維持し、まず使用字形の削減で容量を抑える。太さ別の静的font化は後続の最適化とする。フォントを読み直して必要文字と字形を検査し、元書体での固定配置・字形との比較が通ったものだけを書き出す。字形が欠けたまま保存しない。

各派生フォントの宣言は、認定元の `sourceFontId`・元bytesのhash、サブセット処理のversionと設定、対象字形集合のdigest、出力bytesのhash・byteLength・pathを保持する。元フォントと派生フォントに別の実体IDを与え、CSSの内部familyも分離する。表示名はゴシック体／明朝体等を維持できる。生成時にライセンス・著作権表示・必要な派生書体名を扱う手順も固定する。

現行の完全版hashとの完全一致検証を単に無効化して対応しない。新仕様の派生font validatorで構造・収録範囲・参照関係を検証する。申告された元hashだけで派生の正当性を証明できるとは扱わず、Pressの生成・Horizonアップロード時には元書体と固定した処理から再現照合できるようにする。ローカルファイルの整合性確認は真正性保証とは分ける。

Writingの論理的なfont参照は元書体・版・styleで保持し、各保存ファイルのresource mapが実際のサブセットへ解決する。履歴が古いサブセットhashを指したまま資源を消すことはしない。同じ原本サブセットで必要な字形・機能をすべて満たす場合はそれを参照できるが、原本サブセットの変更や複数subsetへの曖昧なCSS fallbackは行わない。満たさなければWriting用の完全な必要集合を別に収録する。

Writing保存のサブセット生成は端末内で完結する。個人の書き込みや履歴を圧縮のためにサーバーへ送らない。編集用を別端末で再保存する際、完全版が未準備なら既存の必要集合を保持したsubsetを利用する。新しい文字を追加する場合は完全版から対象全体を再生成し、すでに縮小したsubsetから失われた字形を復元しようとしない。

共有用は原本とは別のWriting fontについて現在状態から作り直す。元書体が未準備でも、編集用に収録されたsubsetからさらに絞り込める。字形だけでは過去の文章順序を再現できないが、履歴由来の不要な字形集合も共有ファイルに残さない。

IndexedDBへの自動保存は履歴・本文・資源参照を優先し、1筆ごとにWOFF2を再生成しない。DSFファイル書き出し時に保存対象revisionを固定してサブセットを生成する。サブセット生成が失敗した場合は端末内の編集を保持し、ファイル保存未完了として再試行を案内する。完全版fontを黙って同梱する容量増加fallbackは行わない。

参考: [fontToolsのサブセット仕様](https://fonttools.readthedocs.io/en/latest/subset/)は、文字に加えて保持するOpenType機能から必要字形を収集する。今回のPythonによる容量実測は検証用であり、製品内の生成器を実装済みとするものではない。

## 8 永続する履歴と端末保存

Undo／Redoと履歴一覧の双方を用意する。描画1筆、図形の移動完了、文字入力の確定、削除、全消去を1操作として記録する。入力途中の全pointerイベントやIME変換途中は履歴にしない。

履歴は本全体で一本、直近30操作を保持する。ページごとにUndo履歴を分割しない。見開きをまたぐ一筆は複数ページを変更する一操作とする。Undo／Redoで対象が別ページならそのページへ移動する。

`writing/history.json` の `schemaVersion:2` は基準時点1件と最大30操作の `revisions` を持つ。各revisionは `id,parentId,operation,createdAt,changes`、各changeは `language,pageId,beforeOrder,afterOrder,objects`。objectsの各差分は `id,before,after` を持ち、追加前／削除後はnull。変更のないobjectの筆跡データは履歴へ複製しない。documentの現在ページ群とheadがチェックポイントとなり、そこから双方向差分で全保持状態を再構築する。先頭revisionのparentはnull、changesは空。親参照は直前のrevisionに限定する。

過去へ戻って新しく編集するとRedo側を破棄する。履歴一覧は同じ一本の履歴のheadを移動する。30操作を超えた分は基準時点へ繰り込み、現在の書き込みは削除しない。空の初期状態まで戻せるとは限らない。時刻は端末時刻の参考情報であり、監査証明として扱わない。試作schemaVersion:1の読込時は現在の枝とRedo経路を線形化し、現在内容を保って移行する。

同じWritingの変更ページ・head・履歴をIndexedDBの1transactionで保存する。原本bytesは初回だけ別storeへ保存する。変更していないページや原本を1筆ごとに再保存しない。履歴から参照される資源を削除しない。同じ下書きの多重タブ編集はversion比較で競合を検出し、後勝ちで上書きせず、別コピーとして保存できるようにする。

UIは「この端末に保存済み」「保存中」「端末に保存できません」を区別する。ファイル保存とは別の状態であり、ダウンロード開始だけで端末上のファイル保存完了を断定しない。容量不足時は保存済みのheadを維持し、未保存内容を明示してファイルへの退避を案内する。

履歴パネルには「本全体で直近30操作」とRedo破棄の説明を表示する。件数上限とは別に、展開bytes・JSON・object／point／文字数の安全上限を維持し、超過時は変更前の状態を保持する。ブラウザーデータの削除や保存領域の消去後まで復元を保証しないため、編集用DSFへの定期保存を提供する。

ランタイムは `language/pageId` でページを索引し、変更ページだけを検証・更新する。表示中の1〜2ページと前後各2ページを先読みし、描画cacheは最大6ページ。移動先が変わったら予約を取り消し、範囲外のDOMと確認画面の画像URLを解放する。Reader統合時はReaderが原本を描くため、Writing側で原本DOMを重複生成しない。ZIP全体の検証・展開、書き出し時の全体検証とフォント収集は維持する。ZIPからページを部分取得する方式は今回の対象外。

## 9 編集用と共有用の書き出し

書き出し開始時に原本とWritingのrevisionを固定する。書き出し中に新しい編集があっても、対象revisionを混ぜずに1つの整合したファイルを作る。

編集用には、現在状態、保持中の直近30操作とRedo、削除済みobjectを含む復元に必要な資源を収録する。保持範囲外の履歴と別の枝は収録しない。削除した文章も保持中の履歴に含まれるため、共有には共有用コピーを使う説明を表示する。

共有用は編集用ZIPからhistory entryだけを取り除く方式にしない。原本領域と、選択したrevisionの可視Writing状態から、新しいZIPを組み立てる。履歴、削除済みobject、未使用のWritingリソース、選択状態、clipboard、一時入力、作業時刻履歴を含めない。非表示中のWritingも共有内容のプレビューで確認できるようにし、共有用は現在の確定Writing一式を収録する。

共有用の `headRevisionId` は `null` とし、現在状態を示すための新しい共有コピーIDだけを持つ。プレビューでは「履歴なし・編集ロック済み」を表示する。読者のメール、認証UID、署名鍵はどのDSFにも収録しない。

全方式で、生成したZIPを再展開し、CRC、entry一覧、MIME、hash、原本bytesの一致、Writingの整合性を検証してからダウンロードへ渡す。共有用は削除済み文章を含むfixtureで、その文字列が展開後の全entryに存在しないことまで検査する。

UIには「DSFをダウンロード」「編集用コピーを保存」「共有用コピーを保存」を用意する。通常版のダウンロードが個人Writingを含むことはない。共有用を開いた場合は、その共有用ファイルの保存だけを提供し、Writingを除いた通常版や編集用への変換は提供しない。

## 10 HorizonとPressの提供契約案

Pressの「読者にDSFダウンロード版を提供する」は初期値OFF。作者自身がDSFを端末保存する操作と分ける。ONの場合は同じ組版snapshot・Release IDからHorizon成果物と通常版portable DSFを生成し、両方の検証・アップロードを完了してから公開情報を切り替える。

公開Release情報のdescriptor案は `dsfDownload:{status,formatVersion,releaseId,baseContentHash,byteLength,sha256,downloadPath}`。`ready` はAPIが検証済みZIPの受領を確認した場合にだけ設定できる。未提供の場合はdescriptorを置かない。準備・失敗の状態は作者向け操作記録に持ち、読者向けに不完全なURLを出さない。

片方だけ成功しても「DL版あり」として発行しない。公開ポインタの切り替えは最後に行い、それまでは前の公開Releaseを保つ。R2とFirestoreを跨ぐ単一transactionは仮定せず、アップロード済みreceiptと最後のmetadata transactionで完了を決める。再試行は同じbytesのhashを照合して再利用し、残った未参照ファイルは後で調査できるようにする。

ダウンロードAPIは現在の公開／限定公開／非公開・提供状態を既存の閲覧ルールに従って判定する。ダウンロード用ZIPを無制限公開のURLへ置いたまま、ボタンを消すだけで提供停止したとは扱わない。ZIPの保管先と配信経路は実装計画のW3で確定する。

提供停止後は新規取得・新規Writing開始を止める。すでに取得・検証して端末に確保した原本と書き込みは利用・保存を続けられる。配布済みファイルの回収は保証しない。再公開した最新版へ旧Writingを自動合成しない。

## 11 検証と対象外

2026-10-13の確認版: テキストは代表サイズ20種（8〜144）・1〜360の直接入力（小数可）・1刻みの＋−で指定する。サイズは従来のWriting座標上の値を維持し、ptへの換算は行わない。文字色は基本8色と任意色。線・矢印は描く前と選択後の両方で、始点／終点の有無と先端4種（開いた矢印・三角・丸・ひし形）を設定できる。保存には任意の `arrowHead` を用い、省略は `open`、未知値は拒否する。

暫定の安全上限は履歴256リビジョン（初期状態を含む）、各状態の全ページ合計4,096オブジェクト、点列合計20万点、テキスト合計20万UTF-16コード単位、WritingのJSON全体8MiB。現実装は履歴に各状態を丸ごと保持するため、件数より先にJSON容量上限に達しうる。上限超過の変更は適用せず、現在の状態を保持する。履歴の自動削除は行わない。製品化前に実機負荷測定、容量警告、明示的な履歴整理と差分履歴方式を検討する。

ZIPのunsafe path、重複entry、過大展開、数値のNaN／Infinity、過大なpoints・文字列、未知のobject型、存在しないページ、欠落font、履歴の循環・参照欠落を拒否する。制限は展開・描画の前に段階的に検査し、原本が正常でもWriting検証に失敗したファイルを黙って正常な原本として開かない。

共有用の編集ロックとhash検査を「改ざん防止」「真正性保証」と表示しない。ファイルを解析できる第三者はロック設定とhashを作り直せる。電子署名、署名鍵の信頼管理、暗号化、共同編集、クラウド同期、OCRによる文字選択、過去DSF移行、OSファイルアイコンは初期実装の対象外。

原本の上を不透明な図形で覆っても原本の文字はファイルに残る。Writingは機密情報を除去する墨消し機能ではなく、その用途を案内しない。

## 12 現行仕様との対応

- [ファイル形式](file-format-spec.md): portable ZIP、360×640座標、原本の画像／固定テキスト、同梱font、entry hashの土台。
- [データモデル](data-model.md): Project／Work／Releaseの区別と公開情報の境界。
- [Press](pressroom-spec.md): 組版確定、Horizonとportable成果物の分離。
- [用語](product-terminology.md): リード、Horizon、Reader。本文組版のルビ・圏点で使う既存annotationsはWritingと別物。
- [ページリンク](page-links-editor-integration.md): 原本のページリンク。Writingではリンクや生成ページ番号を変更しない。

本文で提案した形式3はまだ正本へ切り替えていない。実装時はこれらの文書とvalidatorを同時に更新し、古い仕様説明を現在の契約と混在させない。

### 2026-10-12 筆ペン見本と重ね順

- 新規筆ペンは geometryVersion:3 と inkAmount:0〜1 を保存。点列に沿った決定的な補間ノイズで筆筋の途切れ・幅・配置を変え、墨量に応じて6段階の淡い不規則輪郭を重ねる。物理シミュレーションではなく疑似表現。描画時の点列を約1,201点、SVG pathを最大24個に抑える。geometryVersion 1/2 の既存筆跡は従来の描画を維持する。選択後に設定を適用した筆ペンは方式3へ更新する。
- 筆ペン設定の見本は実際の筆跡と同じrendererを使用し、墨量・色・幅に即時追従する。既存オブジェクトへの変更は「選択に設定を適用」で確定する。
- レイヤーは現在のページのWriting objectsの描画順を表示する。配列末尾が最前面。原稿本体は別の不可侵層のため移動対象にしない。最前面／一つ手前／一つ奥／最背面は履歴に記録し、Undo/RedoとDSF再保存で保持する。

### 2026-10-12 筆運び・サムネイル・ドラッグ

- 新規筆ペンは geometryVersion:4。各点に dryness（有限数0〜1）を保存する。入力時の累積距離と速度からカスレを決定し、始端は少なく、運筆の進行と速い区間で増やす。geometryVersion 1〜3 の表示は維持。旧筆跡へ設定を適用する場合、当時の時刻情報は無いため累積距離のみから dryness を補う。
- 再読込時に端末の速度から再計算しない。点列のdrynessは移動、見開き分割、複製にも保持される。設定見本も同一方式で途中に速い区間を設ける。
- レイヤーは実rendererでサムネイルを作り、全体が収まる倍率で表示。右端つまみのPointer Eventsでマウス／ペン／タッチのドラッグを処理する。挿入線、一覧の端で自動スクロール、キャンセル、境界外ドロップ無効、上下キーの代替操作を備える。操作完了時だけ1履歴として配列順を変更する。
- 色・道具設定と文字設定は背景白76%、弱いblur、薄いbackdropにして原稿が透ける。レイヤー／保存パネルの背景は従来のまま。

### 2026-10-12 オブジェクトロックとレイヤーパネル

- 各Writing objectに任意の locked:boolean を追加。省略はfalse。全オブジェクト種別で使用でき、履歴／編集用／共有用DSFに保持する。共有用全体の編集ロックとは別の操作保護。
- レイヤー行に選択（サムネイル／名前）、ロック／解除、削除を配置。ロック中も選択して確認できる。移動・サイズ変更・色等の編集・切り取り・削除・そのオブジェクトを対象とする並べ替えを禁止。他のオブジェクトの並べ替えにより相対的な順序は変わる。
- modelの変更処理でもロック中のオブジェクトの削除／形状変更を拒否し、解除と内容変更を同じ操作で行うことも禁止。ロック・解除・削除はUndo/Redoで復元可能。履歴復元はロック状態ごと復元する。
- レイヤーパネルは背景白66%、弱いblur、backdrop8%。選択結果／重ね順の更新は背後のページに即時反映。
