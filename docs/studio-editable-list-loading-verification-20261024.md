# 編集用リード比較一覧とリーズ読み込み停止の修正

## 実装

編集用リードの一覧を「管理名・リードタイトル・更新日・操作」の表に変更した。管理名とリードタイトルは独立した値として表示し、一方が未設定でも他方を代入しない。更新日は日時を分け、表紙は45×80px（9:16）、角丸なし。タイトル14px、通常項目13px、補助情報12px、行の上下余白16pxなどをリーズに合わせた。ダークテーマでのタイトル色も共通の文字色を指定している。

更新日の新しい順／古い順、管理名の昇順／降順、リードタイトルの昇順／降順を追加した。数字は自然順、未設定値はどちらの方向でも末尾。検索と併用でき、画面内の一覧再描画やリーズとの往復でも並び順を維持する。既存行を並べ替えるため、各行の編集・操作メニューとの対応を維持する。狭い画面では見出し付き項目を折り返す。

リーズの読み込みには次の修正を入れた。

- 共有していた取得中Promiseに待ち時間上限がなく、SDKから応答が来ないと後続の画面も同じ取得を待ち続けていた。取得を15秒で打ち切り、キャッシュから外して再試行可能にした。
- 強制更新・アカウント変更・版の更新による無効化では、古い待機を直ちに解除する。期限切れや無効化後の結果はキャッシュへ戻さず、後続の作品取得も進めない。SDKに既に渡した個別読み取りの通信そのものは中止できないため、遅れて来る結果を無視する。
- スペースの取得にも待ち時間上限を設けた。表示側には20秒の最終期限を置いた。
- 読み込み中も「更新」ボタンを表示する。期限切れ時は未取得を0件とせず、「—」と再試行の案内を表示する。

元のスクリーンショットの発生時に、どの通信が応答を止めたかまでは特定していない。応答しない取得を再現したテストにより、無期限待機を許していた実装と、その解消を確認した。

保存内容・公開状態・URL・権限・ファイル形式は変更していない。

## 自動検証

- `verify-home-project-list`：管理名とタイトルの分離、多言語、日時形式、6種類の並び順、未設定、HTMLエスケープ。
- `verify-edition-list-cache`：同時取得共有、期限切れ、強制更新、無効化、アカウント分離、返答のない取得の打ち切り、再試行、古い結果の破棄。
- `verify-home-dashboard-progressive`、`verify-edition-list-presentation`、`verify-edition-list`。
- `verify-project-display-title`、`verify-project-listing-thumbnail`、`verify-project-title-surfaces`、`verify-viewer-release-route`。
- 変更JavaScriptの構文検査、`git diff --check`、Writing同梱の `build:staging`。

`verify-project-title-surfaces` は廃止済みのWorks/Homeカード関数を検査していたため、現在の版一覧と編集用リード表のタイトル解決経路に合わせた。保存メタデータや言語別タイトルの既存検査は維持した。
