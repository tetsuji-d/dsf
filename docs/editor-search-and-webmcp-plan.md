# エディター検索とWebMCP対応の段階計画

更新日: 2026-09-12
基本方針: [dsf-platform-policy.md](dsf-platform-policy.md#9-webmcpを前提とする機能設計確定方針接続は今後の実装)

## 今回の実装範囲（ローカル検証済み・未デプロイ）

1. 画像からFlow本文編集へ移ると、画像選択・ハンドル・画像用リボンを解除する。画像操作開始時は本文編集モードを終了し、画像操作後の再組版で本文カーソルを復元しない。
2. `js/flow-search.js`にDOMに依存しない原稿検索と結果の有効性検証を用意する。対象はgroup／section／block IDと言語、UTF-16範囲。文字境界はgrapheme単位で検査する。
3. リボンの検索アイコンまたはCtrl/Cmd+Fで検索バーを開く。現在のFlow／作品内の全Flow、言語、大文字小文字、前後移動に対応。キャンバスと原稿モードで現在の一致を選択表示する。Esc／閉じるボタンで閉じる。

- 対象はFlowの見出し・段落本文。固定ページのテキストボックス、キャプション、ルビの読みは今段階の対象外。
- 原文fallbackを翻訳検索の結果にしない。表示できない翻訳へキャンバス移動できない場合は移動失敗を表示する。
- 文字列をそのまま検索する。正規表現、単語単位、段落をまたぐ検索は未対応。
- 初期上限1000件。超えると件数に「+」を付ける。入力は512文字まで。
- 保存元本文と照合して古い結果への移動を拒否する。検索は本文、翻訳確認状態、保存形式を変更しない。
- 一致の全件同時描画ではなく、前後移動で選択中の一致を表示する。
- 検索処理は将来のWebMCP接続から再利用する。現在はツール登録や外部AI接続を実装していない。結果のexpectedTextはエディター内の照合用であり、将来のツール出力に全文をそのまま公開しない。

## 続く単位

4. 置換案と適用コマンドを作る。個別／全置換、原文変更に伴う翻訳状態、ルビ・圏点の範囲、Undo一回、競合・二重適用を検証する。検索表示上限を全置換件数の上限と混同しない。
5. WebMCP接続を分離モジュールで追加する。現在対象の取得・検索から始め、対応クライアントと非対応ブラウザで検証後に置換を接続する。
6. 編集記号、文字数、見出し移動、範囲選択・削除の残課題を整備する。
7. 翻訳・画像配置・キャプション・ページ配置・プレビューへ共通コマンドを拡張する。
8. PWA／オフラインViewer、DSFダウンロード、版管理を別単位で設計・実装する。

共通コマンド化は今回の検索から着手した段階であり、エディター全機能の移行完了ではない。
既存の残実装計画には後続の実装が未反映の箇所があるため、各着手時に現コードと照合する。

## 検証

- `node scripts/verify-flow-search.cjs`: 言語・範囲・記号・grapheme・件数制限・古い検索結果の拒否。
- `node scripts/verify-flow-search-browser.cjs`: 検索バー、ページ／Flowをまたぐ移動、翻訳、原稿モード、JA/EN、検索で原稿が変わらないこと。
- `node scripts/verify-flow-wrap-editor-browser.cjs`: 画像と本文の選択切替、画像リボン操作の選択維持、Flow編集・Viewer preview。
- `node scripts/verify-editor-object-interactions-browser.cjs`: Fixedコピー・貼り付け・Undo・resize・Viewer preview。
- `npm run build:staging`。

ブラウザ検証はローカルChrome。実際のWebMCPクライアント、全OS、stagingでの受け入れ確認を意味しない。
