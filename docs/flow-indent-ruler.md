# Flow 段落インデントルーラー

## 操作

キャンバスのFlow本文をクリックして直接編集を開始すると、横書きはページ上側、縦書きはページ右側にルーラーを表示する。右の編集プロパティには「段落インデント」を表示する。

- **段落全体**：すべての行の開始位置。
- **先頭行**：段落全体の開始位置からの差。負の値はぶら下げ。
- **行末側**：行末の余白。

「段落先頭を1字下げ」はオンで先頭行を1字、オフで0字にする。段落全体・行末側の余白は変更せず、数値入力・ドラッグで先頭行が1字になったときもチェック状態が連動する。必要な本文幅を確保できない場合はオンにできない。本文に全角スペースを追加したり、会話文を自動判定したりはしない。

各ハンドルのドラッグ、方向キー、数値入力で0.5字単位に調整する。「字」はその段落のフォントサイズの1emを表す。実際に収まる文字数は文字幅・約物・注釈などにより異なる。開始側・終了側は最大8字、本文の領域は原則3字分以上を残す。先頭行が本文領域の外に出る値は丸める。

ドラッグ中は対象断片をプレビューし、離した時点で原稿に一度だけ記録して全体を再ページ化する。元に戻す／やり直すは既存の履歴を使用する。補助線、段落の薄い色、編集中の行の色は表示補助で、それぞれの表示設定を編集パネルで切り替えられる。

対象は原文の現在の1段落（見出しを含む）。翻訳の直接編集、複数段落への一括適用、タブ位置の設定はこの単位に含めない。IME変換中、範囲選択中、再ページ化中はインデント操作を無効化する。段落内のEnter分割はインデントを引き継ぐ。見出し末尾のEnterによる新しい本文段落は、既存の新規段落仕様どおり標準書式で開始する。

## 原稿と保存

初めてインデントを設定すると、そのFlowDocumentをschemaVersion 4にする。従来のv1〜v3原稿は設定なし（0字）のまま読める。旧版Studioはv4を扱えないため、インデントを設定した原稿は更新後のStudioで編集する。

```json
{
  "type": "paragraph",
  "texts": {"ja": "本文"},
  "indentByLanguage": {
    "ja": {"start": 2, "first": -1, "end": 1}
  }
}
```

設定はページ番号ではなく意味上の段落と言語に属する。再ページ化で段落が複数ページに分かれても、先頭行インデントは原稿の段落先頭にのみ適用する。原文・翻訳本文、翻訳状態、他の段落はインデント操作で変更しない。既存のProject保存とDSPシリアライズを使い、Firestoreのコレクション構造・Rulesは変更しない。

## 組版と配信

既存のDOM計測・生成ページ・Press組版に同じ論理方向の余白とtext-indentを適用する。組版キャッシュのrendererVersionは15。増分paginationの比較対象に言語別インデントを含める。

発行時は原稿とpagination断片のインデント一致を検査する。配信は計測済みfixedText座標として確定し、公開ViewerにFlowDocumentや編集用のルーラー・補助線・強調色を渡さない。本文を画像化しない。

## 検証

- `node scripts/verify-flow-indent.js`：保存復元、翻訳保持、古い操作の拒否、値の検証、段落分割の継承、ページ継続、増分pagination。
- 関連のauthoring／direct-edit／annotations／title-page／image-insertion／group-join／publication検証。
- 隔離ブラウザで横書き・縦書きの数値入力→ドラッグ、他段落・翻訳保持、2回のUndoを確認。
- ブラウザで複数ページを組版してfixedTextへ投影。先頭ページだけ先頭行字下げがあり、継続ページは段落全体の字下げだけとなることを実座標で確認。断片のインデント改変は発行判定が拒否する。
- staging向けビルド。公開・R2アップロード・デプロイはこの検証に含めない。
