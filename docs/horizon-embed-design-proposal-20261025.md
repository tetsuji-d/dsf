# Horizon埋め込み — 表紙全面表示とカスタムの検討案

## 自動サイズ・ページ切替の合意（2026-10-26）

ユーザー指定により、標準は「自動」。以下は旧案の標準320px固定・常時9:16の外枠・幅の必須選択より優先する。仕様への反映であり、runtime・生成コード・stagingへの実装は未完了。

- 基本操作は「コードをコピーして貼り付ける」だけ。PC用／スマホ用にコードを分けず、幅・高さ・ページ数の入力を要求しない。サイズ指定は詳細設定へ移す。
- 判定は端末名ではなく、貼り付け先のコンテンツ領域とiframe内の実寸を使う。狭い枠は1ページ、十分な幅と高さがある枠は見開き2ページ。PCの細い列も1ページとする。
- 新コードは親幅に追従する外枠を含め、過大なサイズを避ける最大幅・高さ制限を自動適用する。初期検証値は見開き開始幅640px（小口を除く）、最大幅720px、最大高640px。スマホは画面内に収まりやすい高さも考慮する。最終値は実表示で調整し、利用者に調整を求めない。
- 見開き時も各ページの9:16を保つ。タイトル・ロゴ・操作はコンテンツに重ねる。表紙・裏表紙は単独表示し、広い枠では中央へ配置する。この場合の左右の余白は、表紙を切り抜かず本文への移行で外枠を動かさないために許容する。
- 外枠のサイズは親の幅・画面サイズに対して決める。表紙→本文、ページ送り、操作表示の開閉では高さを変えない。画面回転・ウィンドウ変更・全画面への出入りでは再計算し、現在のページを含む表示へ移行する。切替境界付近の往復を防ぐ。
- LTR／RTL、見開きの組み合わせと表紙の扱いは既存Readerの契約を再利用する。読み込み直し・言語切替・view加算をレイアウト変更の副作用として起こさない。
- 詳細設定だけに「自動（推奨）／1ページ／見開き優先」を置く。「常に見開き」という保証はしない。見開き優先でも狭い枠は1ページへ戻し、本文を潰さない。小口あり／なしは別の見た目の選択として維持する。
- iframe内から外側の高さを直接変更できるとは想定しない。生成する外枠側でサイズを決め、Readerは与えられた寸法に適応する。掲載サービスが外枠のCSS等を削除・固定する場合でも、iframe内の自動切替と通常Readerの導線を維持する。Jimdo／Wixの公開ページで貼り付け方法ごとの制約を確認する。
- 既に貼った旧コードの固定480px・9:19指定はサービス側だけでは取り除けないため、新コードへの貼り替えは一度必要。それ以降のPC／スマホ差・画面回転では貼り替え不要を目標とする。

実装順: 外枠と自動レイアウトの共通契約 → コード生成の既定値更新 → Studioの詳細設定と見本 → staging検証。360／390／430px、PC1280／1440px、狭いサイドバー、中間幅、横向き、全画面で、ページ保持・外枠安定・固定本文・権限・view重複防止を確認する。サイト側が指定を固定する例外は、通常の自動動作とは分けて記録する。

## 現状の原因

- `js/embed-policy.js`: 出力コードはmax-width:480px、iframeは9:19。480px幅ならiframeだけで約1013px高になる。親の列幅が狭ければその幅に縮む。
- `css/viewer-embed.css`: 表紙は高さmin(45dvh,280px)。大きいiframeでも表紙だけ小さいまま。
- `js/viewer-embed.js`: 表紙・タイトル・著者・読む・Readerで開くを中央に縦積みし、コードにもiframe外のReaderリンクを付ける。役割が重複している。
- 読書中も独立した固定操作バーを下端に置く。作品と一体のプレイヤーとしての余白・操作設計が不足している。
- JIMDO内で埋め込みが出ていることはユーザー添付画像から確認。JIMDOの編集画面・公開ページで新デザインを実検証したわけではない。

## 推奨：9:16の全面オーバーレイ

### 待機状態

1. 枠自体を9:16、角丸なしにし、表紙を同じ比率で全面表示する。外側のレイアウト余白は作らない。
2. 上端に既存のDマークとタイトルを重ねる。タイトルは最大2行、全文はキーボード/タップでも開ける作品情報に保持する。
3. 中央は本のアイコン付き「読む」。唯一の主操作として52px以上の高さにする。自動開始しない。
4. 下端に小さなHorizonブランドと外部で開く印。これは同じ版のReaderへ移動する導線とし、読み上げ名を「Readerで開く」にする。ホームへの予期しない遷移にしない。
5. 著者・版名は作品情報へまとめ、表紙下に追加の行を積まない。
6. 白い表紙・写真の表紙いずれも、上/下の情報に局所的な暗色グラデーションを敷き、文字とボタンのコントラストを確保する。表紙全体を常時暗くしない。白い表紙には細い境界線を保つ。

表紙自体の白い余白は作品の一部なので残す。枠いっぱいとは拡大して切り抜くことではなく、ページの全体を比率どおりに表示すること。9:16以外の旧版/任意のiframeサイズではcontainして余白を許容し、クロップ・伸長・本文リフローをしない。

### 読書状態

- 中央の「読む」を消し、同じ領域で最初の本文ページを表示。待機/読書で枠高を変えず、掲載先のスクロール位置を飛ばさない。
- 上端の作品情報と下端の操作を本文に重ねる。本文を操作バー分だけ縮めない。
- 下端には前/次・ページ番号・拡大・その他。その他に言語、Readerで開く、作品情報を入れる。対応言語が1つなら言語は省略。
- 読書開始後は短時間（初期案2.5秒）で操作を隠す。本文中央タップ、マウス移動、キーボード操作で再表示。hover専用にしない。
- UIにキーボードフォーカスがある間、メニューを開いている間、操作中は隠さない。隠れているUIをTabで探せない状態にしない。操作を再表示する名前付きの手段を残す。
- 「常に操作を表示」も選択可能。本文の端まで文字がある作品では、中央タップで一時的に全UIを隠して確認できる。
- 拡大は対応環境で全画面。対応しない環境は通常Readerへの移動を明示し、ユーザー操作から開く。iPhone/JIMDOの実機検証が必要。
- 指で縦にスクロールしたときは掲載先HPを読み進められるようにする。初期実装は明示的な前/次ボタンを基本とし、横スワイプは既存Readerとの競合確認後に扱う。

### 比較案：下部操作帯

9:16ページの外に48px操作帯を確保する構成も比較可能。本文に操作を重ねない利点があるが、枠全体が9:16でなくなり縦長になる。現時点の推奨は全面オーバーレイに一本化し、初回から2種類のプレイヤーを実装しない。

## サイズとカスタム

初期値は「標準320px・親幅に応じて縮小・中央配置」。320×約569pxなので従来480px/9:19の約1013px高より小さい。スマホでも無条件に横幅いっぱいへ拡大せず、選択した最大幅を維持する。

|項目|初期案|
|---|---|
|幅|小280 / 標準320 / 大360 / カスタム240〜640px|
|高さ|9:16から自動算出。独立した高さ入力は基本UIに出さない|
|伸縮|親の幅が狭い場合だけ縮小。「親幅いっぱい」は詳細設定の明示選択|
|配置|左 / 中央。初期値中央|
|タイトル|表示 / 非表示。初期値表示。非表示でも作品情報で取得可能|
|初期言語|読者の環境に合わせる / 作品が提供する言語を指定。未対応言語は明示した原文へ戻す|
|操作|自動で隠す / 常に表示。初期値自動|
|枠外の通常Readerリンク|表示 / 非表示。初期値表示、小さい補助リンク1行|

任意のロゴ非表示、広告、自由CSS、任意比率、クロップ、自動読書開始は初期カスタムに含めない。D/Horizonは既存の正式アセットを使う。会話内見本のD文字は配置検討用の仮表示である。

同じ版を異なるHP幅で掲載できるよう、サイズ・配置・タイトル表示等は「今回コピーするコード」の設定とし、版の共通権限に混ぜない。許可ドメインは版全体に対する保存設定として分離する。

後続のユーザー指示により、サイズ入力を通常操作から除き、親幅に応じた自動切替を既定にした。最大幅720px・最大高さ640px／画面高80%、狭い枠は1ページ、十分な幅と高さがある枠は見開き。詳細設定は自動／1ページ／見開き優先と、小口の表示有無を提供する。以下の320px初期値や幅・配置・タイトル設定は当初案であり、今回の実装仕様ではない。

stagingの実装・確認範囲は [検証記録](horizon-embed-responsive-verification-20261026.md) を参照。操作可能なStudio内見本は未実装で、既存の静的表紙見本を維持している。

## Studioモーダル

1. 「埋め込みの許可」: 現行のoff/any/allowlistと保存。版全体に適用。
2. 「表示をカスタム」: 上記の幅/配置/タイトル等。変更で見本とコードを更新。「コードを貼り替えると反映」と表示。
3. 「見本」: 待機/読書中、PC/スマホ掲載幅を切替。中央の読む/操作の開閉も試せる。ネットワーク許可判定・実集計と混同しない。
4. 「コード」: コピーは1つ。許可設定の未保存中は既存どおり無効。見本・コピー・サイズ変更ではviewを増やさない。

カスタムは許可済みパラメーターだけをURL/外側コードへ出力する。クライアント側の表示指定で権限・公開状態・edition IDを変更できない。任意CSS/HTML入力は受けない。

## 枠外リンクと旧コード

通常Readerを開く大きいボタンの重複はなくす。iframe外のリンクは、埋め込み自体がドメイン制限で拒否された時にも使えるため、補助リンクとして残すのを推奨する。見た目を優先する場合だけ非表示を選べるようにし、その役割を説明する。

現在の480px・9:19はJIMDOに貼ったHTMLそのものに書かれているため、サービス側の更新だけでその外枠は変更できない。新コードのコピーとJIMDO側の貼り替えが必要。古いコードは引き続き読み込めるようにし、9:16ページ全体が入るように表示する。新版デザインを既存コードにも適用する場合、480pxの外枠内の余白は完全には消せないことを明示する。

## 実装順

1. 表紙ゲート/読書操作の全面表示、9:16ステージ、オーバーレイ、欠損画像/読み込み/拒否表示。既存コード互換とアクセシビリティを先に確認。
2. 320px初期値・9:16の新コード生成と、カスタムオプションの正規化。既存3引数の呼び出しを維持し、未知/不正値を既定値へ戻す。
3. Studioモーダルにコード単位のカスタムと同じ描画部品を使う計測なしの見本を追加。公開設定保存とコード設定の違いを明示。
4. stagingでPC/スマホ、JIMDO実掲載を検証。本文固定、通常リンク、権限再確認、view集計の既存回帰を実行。

## 合格条件

- 280/320/360/480pxと親幅240px、PC1280/1440、スマホ360/390/430と横向きで目視・実操作。
- 白/写真/画像なし、長い題名、固定テキスト/画像/多言語、1ページ/複数ページ。
- 9:16ページの切り欠き・伸長なし。待機/読書の切替で外枠の高さが変わらない。
- UI非表示時に本文全域を読める。主要操作44px以上、Tab/Esc/戻り、フォーカス中は操作が消えない。
- 初回表示/見本/コピーでview増加なし。読む以降の既存可視時間・ページ操作条件と重複防止を維持。
- 非公開化/埋め込み禁止/許可ドメイン変更に関する既存の制御を維持し、通常リンクは独立して閲覧可能。
- JIMDOの編集プレビューと公開ページを区別して新旧コードを確認。PC幅エミュレーションとiOS/Android実機を分けて記録する。
